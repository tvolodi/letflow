# Test Spec: ISS-0064 — orphaned `tenant_schemas` rows from the direct-provisioning +
on_exit-only test pattern (no reaper)

**Issue:** `docs/issues/ISS-0064.yaml`.
**Design:** `lib/letflow/design/iss064-orphaned-tenant-schemas-fix.md`.
**Fix:** `test/support/tenant_schema_reaper.ex` (new `Letflow.TenantSchemaReaper.sweep_orphans/2`)
plus a three-line addition to `test/test_helper.exs` (a start-of-suite call before
`ExUnit.start()` and an `ExUnit.after_suite/1` end-of-suite call), commit `967aede`
("fix(WF03-ISS0064): reap orphaned tenant_schemas rows at suite boundaries") on
`fix/WF03-ISS0064-20260819`.
**Test tier:** integration (real Postgres via `Letflow.DataCase`, real `CREATE
SCHEMA`/`DROP SCHEMA`, no mocks — DIRECTIVE T-1).

## Bug recap

30+ test files provision a real, non-sandboxed `tenant_schemas` row + Postgres schema
via `Letflow.TenantProvisioning.provision_tenant_schema/1` (or a raw `Repo.insert`) and
rely solely on a manually-registered `on_exit/1` callback to clean up. `on_exit/1` only
runs if ExUnit gets the chance to schedule it — a killed or hard-timed-out test process
silently orphans the row and its real schema. Orphans accumulate across `mix test`
invocations and eventually trip `test/letflow/identity_migration_test.exs`'s
`DropLegacyPublicIdentityTables` guard tests (this is a recurrence of ISS-0048/ISS-0050).
The fix adds a suite-boundary sweep (`sweep_orphans/2`) that reclaims old orphaned rows
at the two points in every `mix test` invocation where nothing legitimate can possibly
still be active: before `ExUnit.start()` and after `ExUnit.after_suite/1` fires.

## Criteria (from the design doc, §10 traceability table)

1. A `tenant_schemas` row old enough to no longer plausibly belong to an in-progress
   test is reclaimed: its real Postgres schema is dropped, and both its `tenant_schemas`
   row and its `tenants` row are deleted.
2. A row younger than `min_age_seconds` is left untouched — the concurrent-invocation
   safety mitigation (design §2.3/§4 INV-R-5) added during CODE-DESIGN-VALIDATOR rework,
   guarding against one `mix test` invocation's sweep destructively racing a
   concurrently-running, unpartitioned invocation's still-in-progress test.
3. A row whose `schema_name` does not match `^tenant_[0-9a-f]{32}$` is skipped (not
   dropped, not crashed on) — defence in depth (design §4 INV-R-1) against a
   raw-`Repo.insert`-written row bypassing `Registration.create_changeset/2`'s own
   format validation, which is exactly ISSUE-FIXER's diagnosed leak path.
4. `sweep_orphans/2` reliably returns `{:ok, %{reclaimed: _, skipped_invalid_format: _}}`
   — the failure-mode contract added during rework (design §3.1/§3.2 step 0/step 4: an
   outer `try/rescue/after` around the whole sweep body, never letting an exception
   escape to either real call site in `test_helper.exs`).

## Test cases — `test/support/tenant_schema_reaper_test.exs`

1. **"drops the real schema and deletes both rows"** (criterion 1) — inserts a real
   tenant (`Repo.insert!`), a real Postgres schema (`CREATE SCHEMA`), and a
   `tenant_schemas` row directly via SQL (mirroring ISSUE-FIXER's diagnosed leak path,
   a raw insert bypassing `Registration`'s changeset) with `provisioned_at` 10,000
   seconds in the past. Calls `sweep_orphans(Repo, 1)` (`min_age_seconds: 1`, so the row
   qualifies without an artificial sleep — exactly the parameter's own stated rationale,
   design §3.1). Asserts `reclaimed >= 1` and that the schema, the `tenant_schemas` row,
   and the `tenants` row are all gone afterward.

2. **"does not touch a row younger than min_age_seconds"** (criterion 2) — same fixture
   shape, but `provisioned_at` set to "now." Calls `sweep_orphans(Repo, 300)` (the
   design's own default). Asserts the schema and both rows still exist afterward — this
   is the test that actually exercises the concurrent-invocation race mitigation from
   design §2.3, not just its presence in the code: if the age filter were absent or
   miswired, this row (old enough to satisfy no other condition) would be dropped and
   this assertion would fail.

3. **"skips an old row with a malformed schema_name instead of attempting a drop"**
   (criterion 3) — inserts a row with an old `provisioned_at` but a `schema_name`
   containing SQL metacharacters (`"not_a_valid_schema_name; DROP TABLE tenants;--" <>
   UUID`) that does not match the required format. Deliberately does not create a real
   schema for this row — if `sweep_orphans/2` ever interpolated the raw value into a
   `DROP SCHEMA` statement rather than validating it first, this is exactly the
   SQL-injection-shaped hazard design §4 INV-R-1 exists to prevent. Asserts
   `skipped_invalid_format >= 1`, that the call does not crash, and that the row (and its
   parent `tenants` row) is left untouched rather than deleted — a fail-closed skip, not
   a fail-open force-drop.

4. **"returns `{:ok, %{reclaimed: _, skipped_invalid_format: _}}`" (two variants)**
   (criterion 4) — one call with an explicit `min_age_seconds`, one with both arguments
   defaulted (`sweep_orphans()`), both against whatever state the DB happens to be in at
   that point (including zero orphans, the everyday case for both real call sites).
   Asserts the return shape and that both counters are non-negative integers. A forced
   DB-level outer failure (e.g. the bulk `SELECT` itself raising) was judged impractical
   to construct without either mocking the DB connection (excluded by DIRECTIVE T-1) or
   corrupting `tenant_schemas`'s own table definition mid-test (destructive to every
   other test file sharing this database) — not covered here; the outer
   `try/rescue/after` structure itself was instead verified by direct code reading
   against the design doc's §3.1/§3.2 contract during TEST-DESIGN-VALIDATOR's review.

## Coverage check

- [x] Every acceptance criterion above has ≥1 test case listed.
- [x] No test depends on wall-clock sleeps or unseeded randomness — age thresholds are
      set via an explicit `provisioned_at` value in the fixture, not by waiting.
- [x] Every fixture is self-sufficient: each test creates its own tenant/schema/row and
      cleans up in `on_exit/1` (best-effort, matching this project's existing
      `tenant_provisioning_test.exs`/`identity_migration_test.exs` idiom for real-commit
      cleanup) rather than depending on another test's state or ordering.
