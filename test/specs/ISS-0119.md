## 1. What ISS-0119 is, and what a regression test for it must prove

`docs/status/requirement_status.yaml` grew past the Read tool's 262,144-byte limit. Every
agent was instructed to "read the file in full before appending" while that read returned a
hard refusal, so the append-only safeguard read as followed while being physically
unexecutable — with no second line of defence anywhere.

The mechanical invariant that re-detects this is therefore: **the volume you are told to
read in full must be small enough to read in full.** That is assertion A3. Everything else
in the file guards the machinery around it.

Each assertion below gets **its own `test` block**. That is not style. ExUnit aborts a block
at its first failed assertion, and A0 is *expected* to fail on a pre-fix tree; had A0 and A3
shared a block with A0 first, A3 would never have executed and the pre-fix run would have
short-circuited on the missing index — the exact "proves nothing about coverage" failure
design §7.1 opens by rejecting. (REVIEWER condition C3, Step 3d; raised as MINOR M1 by
CODE-DESIGN-VALIDATOR.)

## 2. Test cases

| Id | Test block | What it proves — and why it exists, beyond restating the design |
|---|---|---|
| **A0** | *the index exists and current-volume resolution is not degraded* | `current_volume/2` returns `{:index, _}`, never `{:no_index_fallback, _}`. Exists so A3's degraded path can never be **silently** active on a tree that is supposed to have the fix: delete or rename the index and the suite goes red here, instead of quietly resolving to frozen volume 1 and letting an agent append to it. |
| **A1** | *every indexed volume exists on disk, and every volume on disk is indexed* | Bidirectional. Catches a volume created without an index entry (invisible to every agent, since §4's HOW-TO-APPEND resolves the target only through the index) and an index entry whose file was moved or deleted. |
| **A2** | *exactly one volume is current and all others are closed* | Two `current` volumes split the history silently; zero `current` volumes strands the next append with nowhere to go. Neither is visible by reading either file alone. |
| **A3** | *the current volume is within the roll-rule ceilings* | **The ISS-0119 regression assertion and the fail-first proof (§4 below).** Also the standing second line of defence design §6 calls for: even if a DOC-UPDATER turn skips step 6 of the roll rule, CI catches the oversized volume on the next run rather than the next agent hitting a refusal. Resolves the volume through `current_volume/2` and takes the ceilings from the index — it hardcodes neither, which is precisely what makes it directional. |
| **A3b** | *`within_bounds?/3` actually fires at the index ceilings against frozen volume 1* | **Explicitly NOT the fail-first proof** — volume 1 is oversized before *and* after the fix, so this is green in both worlds and is never shown to fail. It is a calibration guard on the detector: it goes red if the helper's line or byte measurement regresses, or if a future agent raises the ceilings toward the tool limits (design §12 #2 forbids that). Kept, and honestly labelled, per design §7.1. |
| **A4** | *every entry in every volume conforms to the documented vocabulary and shape* | Vocabulary drift, minus the index's declared anomalies, plus entry-shape conformance (all five fields, in order, parseable ISO-8601 `at:`). This is the check that was missing while the three `event: SCOPE-CHANGE` entries accumulated. **Currently RED on the fix branch — see §6, this is a real finding, not a broken test.** |
| **A5** | *the on-disk vocabulary-anomaly set equals the index's declared set exactly* | Protects the C2 audit trail in **both** directions. A *new* violation fails (drift). A *missing* one fails — meaning a past entry was silently normalised or deleted, which is the precise act the append-only rule exists to forbid, and which no amount of reading would reliably catch. |
| **A6** | *every closed volume's frozen prefix still hashes to its recorded digest* | The append-only rule's first-ever enforcement mechanism. Volume 1's ~103 historical citations and `iss-0078-pin-rebind-provenance.md:367`'s `:5158` line-number citation are only valid while lines 1–5,766 are byte-identical; A6 makes a silent rewrite fail CI instead of falsifying those citations invisibly. |
| **A7** | *every closed volume's footer names the next volume in the index* | Covers the agent who lands on a closed volume rather than the index — it must be able to walk forward. A closed volume with no successor, or a footer naming the wrong path, is a dead end that no other assertion sees. |
| **A8** | *the current volume's header documents the full vocabulary and the real ceilings* | The header is the copy an appending agent actually reads, so it is the copy that must be machine-pinned. Catches a future volume opened by copy-paste error, a vocabulary extension that skips the header, and a ceiling changed in the index but not in the header. Rebuilds both ceiling restatements from the index and also asserts `default_ceilings/0` matches — leaving exactly three machine-checked copies of the numbers and no unchecked prose copy. |

## 3. The §8 digest — erratum applied, and the value actually computed

REVIEWER's Step 3d condition C1. §8's original Elixir form used
`String.trim_trailing(&1, "\r\n")`, which trims only that exact two-byte suffix.
`File.stream!/1` opens in **text mode**, so on a CRLF checkout the CR is already gone by the
time the line reaches the mapper: the trim matches nothing, the surviving `\n` stays, and
`<> "\n"` appends a second — one extra byte per line, 361,376 bytes hashed instead of
355,610, digest `5c9fda42…657a` instead of the normative value.

`frozen_prefix_digest/2` implements REVIEWER's corrected form. **The trim order is
load-bearing:** `"\n"` first, then `"\r"`, never the literal two-byte `"\r\n"`. That is what
makes it correct on a CRLF text-mode read *and* on an LF/binary read — i.e. portable to CI,
where the checkout is LF.

**The digest this test actually computes**, from
`Letflow.Test.StatusHistory.frozen_prefix_digest("docs/status/requirement_status.yaml", 5766)`
on this CRLF working tree:

```
digest=5a1a64ab0b999da3fd86be90109ecee46b9d538d9e9945c0d39fddb10075a804
```

**It is equal** to the normative Bash value `5a1a64ab…804` and to the
`frozen_prefix_sha256` recorded in `docs/status/requirement_status.index.yaml`. §8's CHECK 5
— which was not dischargeable at Step 3 because this test did not yet exist, and which
ELIXIR-DEV correctly declined to claim — **is now discharged**: A6 is green (§5).

The erratum is recorded inline in `lib/letflow/design/iss-0119-status-file-readability.md`
§8, marked as ruled at Step 3d, per condition C2 — an erratum that lives only in a handoff is
the "recorded where nobody lands" failure ISS-0119 is itself about.

## 6. A4 is RED on the fix branch — an undeclared-drift finding, not a broken test

Reported per instruction rather than tuned away. A4 was implemented exactly as design §7
specifies ("every entry carries all five fields in order with a parseable ISO-8601 `at:`.
Exceptions only as declared in A5"), and on its **first ever run** it found three previously
unknown malformed entries in volume 1:

```
  1) test A4: every entry in every volume conforms to the documented vocabulary and shape
     test/docs/requirement_status_invariants_test.exs:162
     A4 — run-history entries do not conform.

       undeclared vocabulary violations (0):
         (none)

       shape violations (3):
         %{line: 4803, path: "docs/status/requirement_status.yaml", req: "REQ-053", problem: {:field_set_or_order, [:req, :event, :agent, :at]}}
         %{line: 4896, path: "docs/status/requirement_status.yaml", req: "REQ-056", problem: {:field_set_or_order, [:req, :event, :agent, :timestamp, :note]}}
         %{line: 5050, path: "docs/status/requirement_status.yaml", req: "REQ-054", problem: {:field_set_or_order, [:req, :event, :agent, :at]}}
```

- volume 1 line **4803** (REQ-053, `started`) — no `note:` field at all
- volume 1 line **4896** (REQ-056, `started`) — the timestamp field is named **`timestamp:`**, not `at:`
- volume 1 line **5050** (REQ-054, `started`) — no `note:` field at all

**These are genuine, independently verified.** `grep -c` over volume 1 gives 182 `- req:`,
182 `event:`, 182 `agent:`, but only **181 `at:`** and **180 `note:`** — the arithmetic
matches the three entries above exactly. Vocabulary is clean: the only `req:`/`event:` value
violations on disk are the three declared `event: SCOPE-CHANGE` entries, so A5 passes and
A4's vocabulary limb is empty.

**Why the test was not weakened to go green.** This is exactly the class of silent drift
ISS-0119 exists to stop: it accumulated over months with no mechanical check, and the first
mechanical check found it. Suppressing it would produce a test that only ever runs against
already-correct code — proving nothing about coverage.

**Why TEST-DESIGNER did not fix it.** Two reasons, both hard constraints of this step:

1. The remediation lives in `docs/status/`, which this step is explicitly forbidden to touch
   (volume 1 is frozen and pinned by A6, so the entries themselves must **never** be edited —
   correcting them is the rewrite the append-only rule forbids).
2. The index has **no declaration mechanism for shape violations.** `known_anomalies:` is
   keyed `{path, line, field, value}` and A5 asserts it equals the on-disk **vocabulary**
   violation set *exactly*, in both directions. Adding the three shape violations to
   `known_anomalies:` would therefore turn A5 red. Closing this needs a design amendment
   (e.g. a separate `known_shape_anomalies:` key that A4 subtracts and A5 ignores), which is
   CODE-DESIGNER/REVIEWER's call, not TEST-DESIGNER's — and the artefact cleared a hard gate
   on its third pass, with this step authorized to edit **only** §8.

**Routed to ORCH** as an issue on this handoff. Until it is ruled on, A4 is a correct,
informative red.
