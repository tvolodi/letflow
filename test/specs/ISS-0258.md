## Criterion

`mix letflow.check_requirements_registration` (ISS-0231) classifies every requirement
into `:registered | :deferred | :neither | :unclassified`. Its only rule touching
`:deferred` is **R3**, which fires exactly when the rationale is `nil` or `""`, and its
roster header states the contract in words: *"DEFERRED (visible debt — always reported,
never gates)"*.

So any non-empty rationale satisfies R3 **forever**. There is no time dimension and no
re-evaluation against the world: a requirement deferred with a once-true reason stays
green after that reason stops being true. `UNREGISTERED` is now watched; `DEFERRED` is
the state nothing watches — the ISS-0221 failure mode displaced one layer up.

ISS-0258's three acceptance criteria and where each is proved:

| Criterion | Proved by |
|---|---|
| A mechanism surfaces a `DEFERRED` requirement whose stage has since become active, **distinct from** one legitimately deferred pending a not-yet-active stage | `F-STALE-BASIC` / `F-LEGIT-BASIC`, and above all the paired `F-S8-SHAPE-LEGIT + F-HISTORICAL-S4-STALE` group, which asserts both halves of the real historical 13/8 split at once |
| Wired into an actual gate a human/CI will see | `T-TASK-RAISES` (a stale deferral raises `Mix.Error`), `T-TASK-PRINTS-ON-GREEN`, `T-TASK-MISSING-FILE`; the alias wiring itself is verified by RELEASE-VALIDATOR running `mix letflow.check` |
| The design states WHY this is a separate detector | Design §D3; the test-side consequence is `T-REG-STILL-GREEN`, which proves D4's addition to the registration module was actually bounded |

## The two traps this spec is built around

**Trap 1 — the pre-fix failure proves nothing.** The fix *adds* a module, so every test
here fails pre-fix with `UndefinedFunctionError`, which demonstrates only that the module
is new. WF-03's *"when the pre-fix failure is 'the code under test does not exist'"*
clause therefore governs: the fail-first requirement is discharged by **mutating the
shipped logic and recording which tests go red per mutant**. That table is
§"Mutation evidence" below, and it is the load-bearing part of this spec.

**Trap 2 — the live corpus has zero signal for the staleness half.** Re-measured on this
branch:

    0 deferred of 115 entries; 0 stale

With **zero** deferred entries, every live-corpus assertion about S1, S2, S3 and S6
passes *vacuously* and would keep passing under almost every mutation of the staleness
rules. This is not hypothetical: ISS-0231 hit exactly this when PR #495 emptied the
deferred set mid-run and made its headline M1 mutant invisible to every live test.

Consequence, stated so no future reader mistakes the live tests for coverage: **the
hermetic fixture group is the whole test.** The `T-LIVE-*` tests are over-firing guards
plus genuine signal for the status-parsing (MS4C, MS5) and stage-activity (MS1, MS2, MS3)
halves only. Every mutant below is killed by at least one **hermetic** test; no mutant
relies on a live test as its only detector.

## Test inventory

| Test | What it proves |
|---|---|
| `F-STATUS-TOKEN` | every declared status maps to its atom, including whitespace-padded |

### `stage_activity/1` — the §3.3 ruling, pinned value by value

`F-DONE-IS-ACTIVE`, `F-IN-PROGRESS-IS-ACTIVE`, `F-BLOCKED-IS-ACTIVE` (design OQ-1 —
reversing that ruling is one token plus flipping this test, deliberately loud),
`F-PENDING-NOT-ACTIVE`, `F-CANCELLED-NOT-ACTIVE`, `F-UNKNOWN-NOT-ACTIVE`,
`F-EMPTY-STAGE-INACTIVE` (a stage with no requirements is inactive by rule, not by a

not leak activity into each other — asserted in both directions, because only one

### S1 / S2 — the staleness verdict

`F-STALE-BASIC`, `F-LEGIT-BASIC`, `F-STALE-EXITS` (a stale deferral is a *violation*, not
merely a printed verdict — MS11's target), `F-LEGIT-NEVER-GATES` (invariant I4: five

plus an S2 violation, never a silent pass), `F-SELF-EXCLUSION`, and
`F-SELF-EXCLUSION-NOT-GAMEABLE` (two deferrals in one stage do **not** mutually excuse
each other).

### The historical corpus — the one real-world signal

`F-S8-SHAPE-LEGIT + F-HISTORICAL-S4-STALE` is **one test on purpose**. Re-derived from
`git show 75f553d:docs/requirements.yaml`, the 21 pre-PR#495 deferrals were
**9 × S8 + 4 × S9 + 8 × S4**, with the stage/status cross-tab at that commit:

    S4  10 done, 21 pending, 2 cancelled
    S8   9 pending, 1 cancelled
    S9   4 pending

So 13 were legitimate and 8 — the S4 ones, whose rationale `-- see the S8 note above`
pointed at the wrong stage inside a stage already 10 requirements deep — were genuinely
stale weeks before anyone noticed and registered them by hand. The two halves are
asserted together because a rule that gets one half right and the other wrong is
invisible to either half alone.

### S4 — status parsing

`F-STATUS-RAW-TOKEN` (added at Step 4 to close a measured coverage hole — see below),
`F-STATUS-TRAILING-COMMENT`, `F-STATUS-BLOCK-NOTE` (a 2-space `status:` between entries is
not swept into an entry), `F-UNKNOWN-STATUS-FAILS`, `F-TYPO-DOES-NOT-DEACTIVATE` (a typo'd
sibling reds the run rather than quietly un-activating a stage), `F-NO-STATUS-LINE`,
`F-S4-ALL-ENTRIES` (OQ-2: S4 applies to non-deferred entries too).

Two of these are deliberately **two-way** discriminators: under the mutant they target,
both the S4 violation disappears *and* the stage flips activity, so the fixture's stale
deferral silently reads legitimate. That is the exact shape of the bug, not a proxy for it.

### S3 / D6 — the `blocked-by:` hatch

Semantics: `F-HATCH-BASIC`, `F-HATCH-BLOCKER-DONE`, `F-HATCH-BLOCKER-CANCELLED`,

### S6 — hatch acyclicity

### The coverage hole found and closed

Design MS4 as written — "extract `status` as rest-of-line instead of first token" — was
applied and **killed nothing**: 55/55 passed. The trap is defended *twice* (`@status_re`
in the parser and the token split in `normalise_status/1`), so mutating either layer alone
is absorbed by the other and no behavioural assertion can observe it. That is real
robustness, not a test gap in the ordinary sense, but it left MS4 undetected.

Closed by `F-STATUS-RAW-TOKEN`, which pins the **raw stored token** (`entry.status ==
"cancelled"`, not `"cancelled  # MVP-1 milestone dropped, see REQ-101's note"`) — the one
observable that separates the two layers, and one design D4 explicitly guarantees is
stored raw. MS4 now kills 1 test; MS4B (the other layer) kills 1; MS4C (both, the actual
§6.3 failure mode) kills 5, including the two live-corpus tests that carry the real
8-of-115 signal.
