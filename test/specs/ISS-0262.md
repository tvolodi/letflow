**Issue:** ISS-0262 (GH#510). **Run:** `WF03-ISS0262-20260822`, WF-03 Step 4.
**Design:** `lib/letflow/design/iss0262-lint-handoffs-non-json-discovery.md`, sections 2

**Fix under test:** `lib/mix/tasks/letflow.lint_handoffs.ex` — `handoff_files/0` becomes

## Criterion

Before this fix, `handoff_files/0` globbed only `**/*.json`, so any handoff-shaped step
artefact written as Markdown (a "narrative handoff") was structurally invisible to the
linter — not merely unvalidated, but never even enumerated. `mix letflow.lint_handoffs`
could report a clean run while a whole run's worth of step records went unchecked. ISS-0262
closes that gap: discovery now matches any `step*.*` basename regardless of extension, and
a new hard rule H6 flags any non-`.json` match as a discovery-completeness defect in its own
right — independent of whether its content happens to be valid anything.

| Acceptance criterion (from the Step-4 handoff) | Proved by |
|---|---|
| H6 fires on the non-JSON fixture | `F-H6-FIRES-NEW`, `F-H6-CONTENT-NEVER-READ` |
| Existing `.json` handoffs unaffected | The `existing .json handoff behavior (H1-H5) is unaffected` describe block (6 tests) |
| The 10 grandfathered `.md` files classify correctly (grandfathered, not new) | `F-GRANDFATHERED-COUNT`, `F-GRANDFATHERED-DISCOVERED`, `F-GRANDFATHERED-NOT-NEW` |
| The real corpus stays green post-fix | `T-TASK-GREEN` |

## Why this is the ordinary fail-then-pass case, not the mutant clause

`handoff_files/0` and `lint_file/2` both existed **pre-fix** — this is a change to
existing functions (arity/visibility change, plus one new branch inside an existing
function), not the addition of a wholly new module. WF-03's "code under test does not
exist" clause (which requires mutation evidence) governs additions where the pre-fix
failure proves only "the module is new" and nothing about discrimination; that is not the
case here, because the pre-fix functions already existed and the assertions target their
*changed* arity/visibility and the *new* branch's classification behavior specifically.
Per this run's Step-4 dispatch, the ordinary checkout-pre-fix-commit /
confirm-red / confirm-green procedure applies.

## Test inventory

### `handoff_files/1` — discovery (H6)

`F-H6-DISCOVERED` (the fixture is found under an isolated fixture root — the direct
regression test for the broadened glob), `F-H6-KIND` (`handoff_kind/1` classifies it
`:non_json`), `F-H6-DEFAULT-EXCLUDES-FIXTURE` (production discovery, called with its
default `handoffs/` argument exactly as `run/1` calls it, never touches the fixture —
proving the fixture needs no `@grandfathered` entry of its own).

### `lint_file/2` — H6 fires on the fixture

`F-H6-FIRES-NEW` (an un-grandfathered non-JSON file produces exactly one `hard_new` `H6`
violation with `grandfathered: false`, an empty `hard_grandfathered`, an empty `advisory`,
and a message naming the actual extension), `F-H6-CONTENT-NEVER-READ` (the fixture's prose
is not JSON — if `lint_file/2` ever tried `Jason.decode` on it this would surface as a
`PARSE` violation instead of `H6`; asserting `rule: "H6"` is the discriminator design
section 4.2 states must never collapse into `PARSE`).

### Existing `.json` handoff behavior (H1-H5) unaffected

`F-JSON-KIND` (`handoff_kind/1` still classifies `.json` as `:json`), `F-JSON-CLEAN-PASSES`
(a well-formed `.json` handoff still produces zero hard violations),
`F-JSON-H1-STILL-FIRES` (an illegal `status` still gates via H1, unchanged),
`F-JSON-PARSE-STILL-FIRES` (broken JSON still reports `PARSE`, never misrouted to `H6`),
`F-JSON-REAL-GRANDFATHERED-UNCHANGED` (a real pre-ISS-0190 grandfathered `.json` entry —
`handoffs/WF02-REQ023-20260816/step-06-doc-updater.json` — still classifies as
`hard_grandfathered` H3, never `hard_new`), `F-DEFAULT-DISCOVERY-STILL-FINDS-REAL-JSON`
(both pre-existing `.json` naming styles — hyphenated `step-NN-*` and non-hyphenated
`stepNN-*` — are still discovered by the broadened glob; this is the exact regression risk
design section 0.1 flags against a naive `step-*.*` pattern).

### The 10 grandfathered WF03-ISS0258-20260822 `.md` files

`F-GRANDFATHERED-COUNT` (exactly 10 real files exist on disk at the exact paths this suite
and `@grandfathered` both name — a drift guard between the two lists),
`F-GRANDFATHERED-DISCOVERED` (default discovery finds all 10 — they are no longer
invisible), `F-GRANDFATHERED-NOT-NEW` (each classifies as exactly one `hard_grandfathered`
`H6` violation with `grandfathered: true`, and none contributes to `hard_new` — the property
that must hold for these 10 historical files to stay non-gating while a *future* non-JSON
file introduced later would still fail the build).

### `run/1` — the real corpus stays green

`T-TASK-GREEN` — `mix letflow.lint_handoffs` still returns `:ok` and prints
`letflow.lint_handoffs: OK` against the real `handoffs/` tree post-fix (the 10 grandfathered
H6 entries plus the existing 6 grandfathered H1/H2/H3 entries keep `total_new` at 0).
