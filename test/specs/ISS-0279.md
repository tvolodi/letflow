# Test Spec: ISS-0279 — `mix letflow.audit_issue_closures` (issue-closure evidence audit)

**Issue:** `docs/issues/ISS-0279.yaml`.
**Design:** `lib/letflow/design/iss0279-issue-closure-audit.md`.
**Fix:** `lib/mix/tasks/letflow.audit_issue_closures.ex` — net-new `Mix.Task`, modeled
structurally on `lib/mix/tasks/letflow.lint_handoffs.ex`.
**Test tier:** unit/integration (Mix.Task, no live `gh` network call anywhere in this
suite).

## Why this is the MUTATION-required case, not ordinary fail-then-pass

`classify/1`, `tracked_issues/1`, and `grandfathered?/1` are all NET-NEW — none existed
pre-fix. A pre-fix run of the new test file fails universally
(`UndefinedFunctionError`/`Mix.NoTaskError`) for every test, which proves the module is
new and nothing about whether the suite discriminates correct from wrong behavior. Per
`docs/agents/workflows/WF-03_issue_resolving.md`'s "When the pre-fix failure is 'the
code under test does not exist'" section, the fail-first requirement is satisfied here
only by mutating the shipped logic and recording which tests fail per mutant — see
below, and this run's `handoffs/WF03-ISS0279-20260822/step-04-test-designer.json`
`result.summary` for the same numbers.

## Criteria (from the design doc's acceptance surface)

1. `tracked_issues/1` parses every real `github_issue:` field shape found in the live
   `docs/issues/*.yaml` corpus: bare integer, bare (unquoted) URL, quoted URL, and
   null/absent (skipped, not tracked).
2. `classify/1` decides `:violation` (ZERO_EVIDENCE) iff `state == "CLOSED"` AND
   comments are empty AND `closedByPullRequestsReferences` is empty; `:ok` if either
   comments or a PR ref is present (invariants I1/I2); `:not_closed` if the issue isn't
   `CLOSED` at all. Both live `gh` comment shapes (bare array vs. `%{"totalCount" => n}`
   object) are honored.
3. `grandfathered?/1` correctly separates a known pre-existing violation (reported but
   non-fatal) from a new one (fails the run) — tested by real membership, not a stub.
4. No test in this file makes a live network call to `gh`.

## Test cases — `test/mix/tasks/letflow.audit_issue_closures_test.exs`

### `describe "tracked_issues/1 -- github_issue field-shape parsing"`

Fixture `docs/issues/*.yaml`-shaped files written to an isolated tmp dir per test
(`Path.expand/1`'d — `System.tmp_dir!/0` returns a mixed-separator path on Windows that
`Path.wildcard/1` silently fails to match without normalizing first; this was caught
during this run — see anti-pattern note below).

- `F-BARE-INT` — `github_issue: 205` (bare integer) is parsed.
- `F-BARE-URL` — `github_issue: https://github.com/.../issues/1` (unquoted URL) is
  parsed.
- `F-QUOTED-URL` — `github_issue: "https://github.com/.../issues/206"` (quoted URL) is
  parsed.
- `F-NULL-ABSENT` — `github_issue: null` is skipped (not tracked).
- `F-FIELD-ABSENT` — no `github_issue:` line at all is skipped.
- `F-ID-FALLBACK` — missing `id:` falls back to the filename stem as `ref`.
- `F-MULTIPLE-SORTED` — multiple tracked files return sorted by path.
- `F-TRACKED-REAL-CORPUS-NO-CRASH` — parses the REAL `docs/issues/` corpus (no `gh`
  call, pure local file read) and asserts shape invariants only (positive integer
  numbers, non-empty refs) — proves the regex handles every real shape in the repo
  today, matching the module's own "Discovery notes" claim.

### `describe "classify/1 -- ZERO_EVIDENCE vs OK decision"`

Direct fixture maps, no I/O:

- `T-VIOLATION-ARRAY` / `T-VIOLATION-TOTALCOUNT` — both live `gh` empty-comments shapes
  (`[]` and `%{"totalCount" => 0}`) with empty refs both classify `:violation`.
- `T-OK-HAS-COMMENT-ARRAY` / `T-OK-HAS-COMMENT-TOTALCOUNT` — either comments shape with
  ≥1 comment classifies `:ok` regardless of refs (I1).
- `T-OK-HAS-PR-REF` — zero comments but a non-empty PR ref classifies `:ok` (I2).
- `T-OK-BOTH-PRESENT` — both present classifies `:ok`.
- `T-NOT-CLOSED-OPEN` — `state == "OPEN"` always classifies `:not_closed`, regardless of
  comments/refs.
- `T-MISSING-REFS-KEY` — refs key entirely absent defaults to `[]` (still eligible for
  `:violation`).
- `T-MISSING-COMMENTS-KEY` — comments key absent hits `comments_empty?/1`'s catch-all
  clause (`false` for any non-list, non-`%{"totalCount" => _}` shape, including `nil`) —
  pins this exact documented edge behavior.

### `describe "grandfathered?/1 membership -- integration via run/1 with a faked gh"`

`grandfathered?/1` is `defp` with no exported test seam, and `run/1` hardcodes
`@issues_dir` so it cannot be redirected to a fixture dir. Tested via a real end-to-end
`run/1` invocation against the REAL `docs/issues/` corpus (never mutated, never
written to) with this OS process's `PATH` monkey-patched (restored via `on_exit`) so
`System.cmd("gh", ...)` inside `fetch_issue/1` resolves to a fixture `gh.bat` script
this test controls instead of a real network call. Two REAL, already-tracked GitHub
issue numbers are targeted: `68` (an existing real `@grandfathered` entry, traced to
`docs/issues/ISS-0012.yaml`) and `15` (a real tracked number, `docs/issues/ISS-0009.yaml`,
NOT grandfathered). Every other real tracked number gets a fixture `OPEN` response so it
never becomes a violation and never pollutes the assertion.

- `T-GRANDFATHERED-VS-NEW` — `run/1` raises `Mix.Error` reporting exactly 1 new
  violation; stdout's `NEW HARD VIOLATIONS` section names GH#15 (never GH#68); stdout's
  `GRANDFATHERED` section names GH#68 (never GH#15). This exercises `grandfathered?/1`'s
  actual membership logic against two real, named numbers, not a mock replacing the
  function under test.
