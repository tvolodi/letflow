# Test Spec: ISS-0400 — `collect_leaf_gateways/3` does not resolve a
# `PARALLEL_GATEWAY` nested inside a fork branch

**Issue:** `docs/issues/ISS-0400.yaml`, severity MINOR.
**Design:** `lib/letflow/design/iss0400-nested-parallel-gateway-fix.md` (revision 2,
gate-approved — §4 specifies the fixture/assertion shapes these tests implement).
**Fix under test:** `lib/letflow/engine/transition.ex` — `collect_leaf_gateways/3`'s
step-4 `:PARALLEL_GATEWAY` clause now dispatches on `gateway_role/2`: a real
join/pass-through node keeps today's immediate-terminal behavior unchanged, while a
nested `:split` node is resolved recursively via the new `resolve_nested_split/3`
(threading the outer walk's live Tarjan state — `memo`/`index`/`lowlink`/`stack`/
`stack_set` — through unmodified, no reset at this boundary) before the outer walk
continues past the nested split's own inner join.
**Fix commit (this run, `feature/WF03-ISS0400-20260901`):** `28422ff9` — "fix: ISS-0400
resolve nested PARALLEL_GATEWAY split during leaf lookahead".
**Pre-fix baseline:** `main` at `58e3c64e` (ISS-0398's fix merged, ISS-0400's not).
**Test code:** `test/letflow/engine/parallel_gateway_test.exs` — 6 new fixtures
(`nested_parallel_split_graph/0`, `nested_split_dead_end_graph/0`,
`nested_split_ancestor_back_edge_graph/0`,
`nested_split_ancestor_back_edge_no_escape_graph/0`,

**Run:** `WF03-ISS0400-20260901`, Step 4.

## 1. Test cases and why each exists

| Test | Fixture (design §4) | Proves |
|---|---|---|
| "a nested split/join pair inside one branch resolves recursively and the outer split succeeds against the real outer join" | Fixture 1, `nested_parallel_split_graph/0` — ISSUE-FIXER's own repro 1 shape | The core regression: before the fix, `collect_leaf_gateways/3` reports the nested `inner_split`'s own `node_id` as branch 1's leaf and the outer split fails with `{:error, {:no_matching_join_found, "outer_split"}}`. Post-fix, `resolve_nested_split/3` resolves the inner split/join pair and continues past it, so the outer split succeeds and resolves against the real `outer_join` — never `inner_split`/`inner_join`. |
| "the nested split still functions as its own independently-dispatchable PARALLEL_GATEWAY split once a token actually reaches it" | Fixture 1's own §4 runtime-boundary requirement | The fix is scoped to the **lookahead search** (`find_matching_join/2`/`collect_leaf_gateways/3`), not `dispatch_parallel_gateway/4`'s own **runtime** dispatch. Advances a real token onto `inner_split` (via `{:complete_task, _}`, since "pre" is a `:HUMAN_TASK` with no automatic outgoing traversal) and confirms it independently splits and registers its own `JoinCounter` under `inner_join`, exactly as any other `PARALLEL_GATEWAY` split would. |
| "a nested split with one internal branch dead-ending fails the whole outer split cleanly" | Fixture 2, `nested_split_dead_end_graph/0` (negative) | A nested split whose own inner resolution fails (one branch dead-ends without reaching `inner_join`) must propagate as `:dead_end` (design §3.3) and fail the **outer** branch — not partially succeed, not crash. |
| "the branch resolves successfully against the real outer join, and terminates, when a nested split's own branch loops back to the ancestor node that led into it" | Fixture 3, `nested_split_ancestor_back_edge_graph/0` — CODE-DESIGN-VALIDATOR's own counterexample, reproduced exactly | The direct regression assertion for the BLOCKER found in design iteration 1: under a reset-based `resolve_nested_split/3`, this exact graph shape (`outer_split → A → inner_split`, with `inner_split`'s own branch `ia → A` looping back to the still-open ancestor `A`) recurses forever. Under this revision's no-reset mechanism, the SCC `{A, inner_split, ia}` closes as one unit at `A`, and the escape path (`ib → inner_join → post → outer_join`) supplies the correct shared leaf value. Completing at all (in bounded time) is itself part of what this test proves, not merely the returned value. |
| "a nested split's branch that loops back to the ancestor with no escape edge anywhere in the cycle fails the whole outer split cleanly, without hanging" | Fixture 3b, `nested_split_ancestor_back_edge_no_escape_graph/0` — negative twin of fixture 3 | Retains the pure-cycle-no-escape coverage design iteration 1's own fixture 3 had: the SCC `{A, inner_split, ia, ib}` closes with an **empty** aggregate leaf set (no edge in the SCC reaches a `PARALLEL_GATEWAY` terminal) — a non-singleton-agreement failure per §2.5's unchanged rule. Same non-regression (no-hang) requirement as fixture 3. |
| "a nested split whose own branch contains a second, deeper nested split still resolves recursively to the real outer join" | Fixture 4, `doubly_nested_parallel_split_graph/0` — arbitrary-depth confirmation | Confirms §3.4's termination/recursion argument holds at depth 2, not only depth 1, and that memoization correctly threads through two levels of `resolve_nested_split/3` recursion — neither nested split's own id, nor either inner join's, ever becomes a `JoinCounter` key. |
