# Test Spec: ISS-0522 — cursor id-component UUID cast guard

**Issue:** ISS-0522 — `Letflow.Entities.Definitions.list_definitions/2` raised an
unhandled `Ecto.Query.CastError` when a caller-supplied pagination cursor carried a
malformed (non-UUID) id component, instead of returning `{:error, :invalid_cursor}`.
Named by REVIEWER during `WF02-REQ231-20260907` as a recurring "unhandled raise on
malformed cursor component" pattern; diagnosed by ISSUE-FIXER this run
(`WF03-ISS0522-20260907`) and confirmed the only real call site today is
`list_definitions/2` (the issue's own "2 call sites" framing was found inaccurate —
the second named site, `lib/letflow/entities/query/cursor.ex`, does not exist yet;
REQ-231 is still pending).

**Run:** WF03-ISS0522-20260907, WF-03 Step 4. **Design:**
`lib/letflow/design/iss0522-cursor-uuid-cast-guard.md` (see §1 for the new helper's
contract, §2 for the propagation path, §4 for the test-ability checklist this spec
follows). **Fix commits:** `b26db044` (issue record), `6ea959df` (fix). **Test
commit:** `c738ec5e`.

**Code under test:** `Letflow.Api.Pagination.cast_binary_id_component/1` (new,
`lib/letflow/api/pagination.ex`) — `@spec String.t() :: {:ok, Ecto.UUID.t()} |
{:error, :invalid_cursor}`, delegates to `Ecto.UUID.cast/1` and translates its bare
`:error` into this module's established `{:error, :invalid_cursor}` shape, with a
defensive non-binary-input clause returning the same error rather than a
pattern-match failure. Used inside `decode_list_definitions_seek/1`
(`lib/letflow/entities/definitions.ex`) before the id component ever reaches a query,
so the id is validated ahead of `filter_by_list_definitions_cursor/2`'s `where:
{e.inserted_at, e.id} < {^inserted_at, ^id_str}` clause against
`EntityDefinition.id` (`:binary_id`).

---

## AC1 — the helper itself accepts a valid UUID and rejects anything else, without
## raising

**Criterion (from `docs/issues/ISS-0522.yaml` / design §1):** a new, reusable
`Letflow.Api.Pagination.cast_binary_id_component/1` helper exists, returns `{:ok,
Ecto.UUID.t()}` for a syntactically valid UUID string, and returns `{:error,
:invalid_cursor}` — never a raise — for any non-UUID string, including edge shapes
(empty string, a string with a UUID's exact length but non-hex content) and
non-binary input.

**Why this exists, not just what it restates:** the defect was specifically an
*unhandled raise*, not merely a wrong return value, so a test that only checks the
success path would miss the entire point of the fix — the failure-path assertions are
what prove `Ecto.UUID.cast/1`'s bare `:error` is actually being translated rather than
left to propagate or ignored. The UUID-length-but-non-hex case exists because a
length-only check would be a plausible-but-wrong alternate implementation (e.g. `byte_size
== 36`) that this test would catch and a naive one would not; the non-binary case
exists because `id_str` at the real call site comes from `String.split/3` on
caller-controlled bytes (design §1's own noted defensive clause), so a caller passing
something already-malformed in a different way must not crash the guard itself.

**Test cases** (`test/letflow/api/pagination_test.exs`, `describe
"cast_binary_id_component/1 (ISS-0522)"`):
- `"a valid UUID string casts to {:ok, binary}, matching Ecto.UUID.cast/1's own shape"`
- `"a non-UUID string is rejected with {:error, :invalid_cursor}, not a raise"`
- `"an empty string is rejected with {:error, :invalid_cursor}"`
- `"a UUID-length string with non-hex characters is rejected"`
- `"non-binary input is rejected with {:error, :invalid_cursor} instead of a
  pattern-match failure"`

## AC2 — `list_definitions/2` returns `{:error, :invalid_cursor}`, not a raise, for a
## cursor with a malformed id component

**Criterion:** given a cursor whose id component is not a valid UUID,
`list_definitions/2` returns `{:error, :invalid_cursor}` and never reaches
`Repo.all/2`/`Ecto.Query.CastError`.

**Why this exists, not just what it restates:** this is the end-to-end reproduction of
the actual reported defect (unit coverage of the helper alone would not prove the
call site was ever wired to use it) — it mirrors ISSUE-FIXER's own reproduction from
the WF-03 diagnosis step, and asserts a clean return value rather than
`assert_raise`, since the entire point of the fix is that nothing raises any more. A
regression that re-inlines the raw `id_str` into the query (skipping the new cast)
would make this test fail with an `Ecto.Query.CastError`, not merely a wrong return —
so this test genuinely distinguishes "guard is wired in" from "guard exists but is
unused."

**Test case:** `"ISS-0522: a cursor with a malformed (non-UUID) id component returns
{:error, :invalid_cursor}, not a raise"` (`test/letflow/entities/definitions_test.exs`).
Builds the malformed cursor via `Pagination.build_raw_cursor_timestamp_key/4` +
`Pagination.encode_cursor/1` under `@list_definitions_cursor_prefix`, with
`"not-a-uuid"` in the id position — the same shape a real caller-supplied cursor
takes, not a synthetic bypass of the encoding.

## AC3 (non-regression) — a valid cursor still paginates cleanly

**Criterion:** a cursor with a well-formed UUID id component continues to page through
`list_definitions/2` results exactly as before this fix (existing REQ-226/067 cursor
contract unchanged).

**Why this exists, not just what it restates:** the new cast is a rejection path
inserted directly ahead of every cursor-driven query for this endpoint; without a
passing-case test alongside the rejecting-case test, a defect that rejected *all*
input (not just malformed input) would make AC2 pass while silently breaking every
legitimate paginated caller — the exact kind of regression a fix-only test suite
would miss.

**Test case:** `"ISS-0522: a cursor with a valid UUID id component still paginates
cleanly (non-regression)"` (`test/letflow/entities/definitions_test.exs`). Creates 3
definitions, pages through with `page_size: 2`, and asserts both the first page's
`next_cursor` round-trips through `list_definitions/2` a second time and the second
page terminates (`next_cursor == nil`) with the remaining item.

## Fail-then-pass proof (evidence this is a genuine regression test, not vacuous)

Per commit `c738ec5e`'s own message: checked out `6ea959df~1` (the commit immediately
before the fix) for `lib/letflow/api/pagination.ex` and
`lib/letflow/entities/definitions.ex` only, keeping this test file at its new
(post-fix) content, and ran the two affected test files.

- **Pre-fix (`6ea959df~1`'s source, new tests present):** 25/26 — the AC2 test failed
  with a real, unhandled `Ecto.Query.CastError` raised at `definitions.ex:318`
  (`value "not-a-uuid" cannot be dumped to type :binary_id`), i.e. the exact defect
  this issue reports, reproduced live rather than asserted. (`cast_binary_id_component/1`
  itself does not exist pre-fix, so AC1's tests would fail to compile/reference an
  undefined function in a real pre-fix run of the full module — the fail-then-pass
  proof as executed targeted the AC2 end-to-end case specifically, which is the one
  that reproduces the reported raise without requiring the new function to exist.)
- **Post-fix (`git checkout HEAD --` restoring the real fix):** 26/26 clean.
- **Full suite for both affected test files against the real fix:** 71/71 passed
  (`test/letflow/api/pagination_test.exs` + `test/letflow/entities/definitions_test.exs`).

This demonstrates the AC2 test genuinely distinguishes pre-fix from post-fix
behavior — it is not a test that only ever runs against already-correct code.
