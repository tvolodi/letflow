## Scope split — what is and isn't unit-testable here

ISS-0712's fix has two parts with very different testability in this environment:

1. **`resolveCredential(envVarName, localDevFallback)`** — a pure function with no I/O
   beyond reading `process.env`. Fully unit-testable, and is this spec's subject.
2. **`loginViaRealOidcRedirect(page, username, password, expectedUrl)` and the spec-file
   change that calls it** — these drive a real Playwright `Page` against a real
   Keycloak-hosted login form and a real `/auth/callback` OIDC exchange. **NOT
   unit-testable in this environment**: there is no live Keycloak instance or browser
   stack available to TEST-DESIGNER. Per ISS-0712's own `fix_direction`, the actual
   proof that this path exercises `OidcCallbackPage.tsx`'s role-conditional redirect is
   deferred to UAT-RUNNER re-running
   `test/fixtures/uat/scenarios/platform/platform-login-routing-by-role.yaml`'s
   PLATFORM_ADMIN branch for real against QA — not to a unit test written here. No test
   is manufactured against this part; attempting one (e.g. mocking `page.goto`/
   `page.fill`/`page.waitForURL`) would only assert that the mock does what the mock was
   told to do, not that the real redirect works.

## Criteria (secondary finding in ISS-0712.yaml)

> add an env-var credential path to helpers.ts (...) so a real environment run never
> needs an ad-hoc, reverted source edit to supply a real credential.

1. Env var set and non-empty → `resolveCredential` returns it (trimmed).
2. Env var unset → returns the supplied local-dev fallback.
3. Env var set but empty or whitespace-only → returns the fallback (an accidentally
   blank env var must not be treated as "a real credential was supplied").

## Test cases — `web/tests/unit/resolveCredential.test.ts`

1. **TC-RC-01** — env var set and non-empty → returns it.
2. **TC-RC-02** — env var unset → returns fallback.
3. **TC-RC-03** — env var set to empty string → returns fallback.
4. **TC-RC-04** — env var set to whitespace-only (`'   \t  '`) → returns fallback.

Per `docs/agents/workflows/WF-03_issue_resolving.md`'s "When the pre-fix failure is 'the

`git worktree` used this run) and recording which tests fail per mutant.

### Mutants applied to `resolveCredential` (web/tests/e2e/helpers.ts)

Baseline (unmutated, current `main`-bound code):

```ts
export function resolveCredential(envVarName: string, localDevFallback: string): string {
  const raw = process.env[envVarName]
  const value = (raw ?? '').trim()
  if (value.length == 0) return localDevFallback
  return value
}
```

Baseline run: `5 passed (5)`.

**Mutant A — drop the `.trim()`** (`const value = (raw ?? '')`):

- Result: **2 tests failed / 5** — TC-RC-04 (whitespace-only env var no longer treated
  as empty: returned `'   \t  '` instead of the fallback) and TC-RC-05 (returned
  `'  real-secret  '` untrimmed instead of `'real-secret'`).
- Proves the suite is sensitive to the trim specifically, not just to gross breakage.

**Mutant B — invert the empty-check condition**
(`if (value.length != 0) return localDevFallback`):

- Result: **5 tests failed / 5** — every case now returns the wrong branch (a
  non-empty value returns the fallback instead of itself, and an empty/whitespace value
  falls through to `return value` — the empty string — instead of the fallback).
- Proves the suite is sensitive to the branch condition's polarity.

**Mutant C — ignore the env var entirely, always return the fallback**
(`return localDevFallback` as the function's only line):

- Result: **2 tests failed / 5** — TC-RC-01 (real value present, expected it back, got
  the fallback) and TC-RC-05 (same, plus would have masked the trim too).
- Proves the suite is sensitive to the env var being read/used at all, not just to its
  formatting.
