# Test Spec: ISS-0719 — `oidc_issuer_base/0` must read `:keycloak_base_url`, not the retired `:issuer` key

**Issue:** `docs/issues/ISS-0719.yaml`.
**Design:** `lib/letflow/design/iss-0719-tenant-config-oidc-issuer-fix.md` §4.
**Fix under test:** `lib/letflow/routers/tenant_config.ex`, `oidc_issuer_base/0`
(~line 331) — now reads
`Application.get_env(:letflow, :oidc, [])[:keycloak_base_url]` in place of the
retired `[:issuer]` key, and returns the value unchanged (no `String.split/2`
post-processing).
**Test code:** `test/letflow/routers/tenant_config_oidc_issuer_test.exs` (new file,
`async: false`, kept separate from `test/letflow/routers/tenant_config_test.exs`
because it mutates the global `config :letflow, :oidc` application env).

---

## 1. Why a separate file, and why `async: false`

`test/letflow/routers/tenant_config_test.exs` runs `async: true` and never touches
`Application` config. These three tests need to swap `config :letflow, :oidc`'s
`:keycloak_base_url` (and, for one case, `:issuer`) live via
`Application.put_env/3` to prove `oidc_issuer_base/0` actually reads the compiled
value rather than coincidentally matching a hardcoded default. `Application` config
is process-shared VM state (an ETS table), so mutating it is only safe under
`async: false`, guaranteeing no `async: true` test observes the swapped value
concurrently — same reasoning and pattern as
`test/letflow/plugs/auth_pipeline_configurable_verifier_test.exs`. Each test restores
the original config via `on_exit/1` even on failure.

## 2. Why test-env's default config could never have caught this bug

`config/test.exs` sets `keycloak_base_url: "http://localhost:#{keycloak_port}"`,
which resolves to `"http://localhost:8082"` under this workspace's default
`config/keycloak_port.exs` — byte-identical to `@default_idp_base_url`. Pre-fix,
`oidc_issuer_base/0` read the retired `:issuer` key (always `nil` since REQ-370), so
`idp_base_url/0` fell through to `@default_idp_base_url`. Post-fix, it reads
`:keycloak_base_url` and returns `"http://localhost:8082"` directly. Both paths
produce the identical final string under the *default* test config, which is exactly
why no existing assertion in `tenant_config_test.exs` moved and why the bug shipped
unnoticed — a test that never overrides `:keycloak_base_url` away from the default
cannot distinguish "reads the right key" from "reads the wrong key and gets lucky."
These three tests exist specifically to break that coincidence.

## 3. Test cases

### 3.1 Fail-then-pass proof: distinctive `keycloak_base_url` is reflected in `oidc_authority`

Sets `:keycloak_base_url` to `"https://auth.qa.bizdala.com"` — deliberately **not**
`"http://localhost:8082"` — and asserts `GET /api/tenant-config`'s `oidc_authority`
is exactly `"https://auth.qa.bizdala.com/realms/bpm-default"`. This is the test that
would fail against the pre-fix code (see §4) and is the primary regression proof
this issue requires: it can only pass if `oidc_issuer_base/0` genuinely reads the
live `:keycloak_base_url`, since the configured value shares no substring with the
old default that a coincidental pass could hide behind.

### 3.2 Unset (`nil`) `keycloak_base_url` falls back gracefully, no crash

Sets `:keycloak_base_url` to `nil` (key present, value absent — the realistic shape
of an incomplete config, distinct from the key being entirely missing) and asserts
the request still returns `200` with `oidc_authority` resolving through the `||`
chain in `idp_base_url/0` all the way to `@default_idp_base_url`
(`"http://localhost:8082/realms/bpm-default"`), matching the moduledoc's
never-error rule (INV-5). Proves `oidc_issuer_base/0`'s
`is_binary(base_url) and base_url != ""` guard correctly rejects `nil` instead of
raising or returning it as-is.

### 3.3 Retired `:issuer` key is truly ignored (negative check)

Sets `:issuer` to `"http://some-other-host/realms/x"` **alongside** a `nil`
`:keycloak_base_url`, and asserts `oidc_authority` does **not** derive from
`some-other-host` — it still falls through to `@default_idp_base_url`. Confirms the
retired key is genuinely dead in the new code, not silently still load-bearing via
some other path (design §4, item 2). This is the third test specified by the design
doc's §4 list; the design doc's own item 3 (a source-grep for `[:issuer]`/
`[:keycloak_base_url]` string literals) is marked "optional, low-value" there and is
subsumed by this behavioral check, which is strictly stronger evidence that
`:issuer` has no effect than a source-grep would be.

## 4. Fail-first proof (verified, not assumed)

Checked out the pre-fix revision of `lib/letflow/routers/tenant_config.ex`
(`oidc_issuer_base/0` reading `[:issuer]`, commit `10ca7a48` per the design doc's own
citation) and ran test 3.1 (`tenant_config_oidc_issuer_test.exs`, first `test` block)
against it in isolation:

```
mix test test/letflow/routers/tenant_config_oidc_issuer_test.exs:66
```

Ran the full file (all 3 tests) against the checked-out pre-fix revision:

```
mix test test/letflow/routers/tenant_config_oidc_issuer_test.exs
Result: 1/3 passed
```

Test 3.1 failed exactly as predicted:
```
assert body["oidc_authority"] == distinctive_base_url <> "/realms/bpm-default"
left:  "http://localhost:8082/realms/bpm-default"
right: "https://auth.qa.bizdala.com/realms/bpm-default"
```
— exactly the ISS-0719 defect reproduced under test: pre-fix, `oidc_issuer_base/0`
reads the always-`nil` `:issuer` key, so `idp_base_url/0` falls through to
`@default_idp_base_url` regardless of the configured `:keycloak_base_url`.

Test 3.3 also failed pre-fix, for a reason worth recording precisely (this
correction supersedes an earlier draft of this spec that assumed it would pass
pre-fix by coincidence): the pre-fix code's `[:issuer]` lookup, unlike `nil`, DOES
find `:issuer` when the test sets it, and applies its old
`String.split("/realms/") |> List.first()` post-processing to it — so with
`issuer: "http://some-other-host/realms/x"` set, pre-fix `oidc_issuer_base/0`
returns `"http://some-other-host"`, and `oidc_authority` becomes
`"http://some-other-host/realms/bpm-default"`, failing the
`refute body["oidc_authority"] =~ "some-other-host"` assertion. This is in fact
*stronger* regression evidence than originally planned: it proves the retired
`:issuer` key was still fully load-bearing pre-fix (the opposite of "safely dead"),
and that the fix genuinely severs that path, not merely adds a new one alongside it.
Test 3.2 (nil `keycloak_base_url` fallback) passed both pre- and post-fix, as
expected — `nil` was never affected by which key `oidc_issuer_base/0` reads, since
both `[:issuer]` and `[:keycloak_base_url]` are absent/nil in that setup.

Post-fix (current `tenant_config.ex`, reading `:keycloak_base_url`): all 3 pass —
```
mix test test/letflow/routers/tenant_config_oidc_issuer_test.exs
Result: 3 passed
```

The pre-fix file swap was done via `git show 7cd2a420^:lib/letflow/routers/tenant_config.ex`
(the parent of the fix commit) written over the working file, then restored via
`git show 7cd2a420:lib/letflow/routers/tenant_config.ex` (equivalently, `git checkout --`)
afterward; `git status --porcelain lib/letflow/routers/tenant_config.ex` confirmed a
clean working tree post-restore.

## 5. Existing coverage left unaffected

Per design §4: no assertion in `test/letflow/routers/tenant_config_test.exs` or
`test/letflow/routers/req078_supporting_routes_test.exs` changes — both files
already only assert against `idp_base_url/0`'s *value* under the default test
config, which is unchanged by this fix (only *which branch* of the `||` chain
produces it changed). This spec's new file is purely additive.
