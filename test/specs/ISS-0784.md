## History: the defect this spec originally found (site 3), now fixed

**Original finding (this session, prior pass):** the site-3 test, run against the
as-shipped ISS-0784 implementation, found `Repo.all(Audit.Entry, ...) |>
Enum.filter(&(&1.action == "task_activation.rejected"))` returning `[]` — no audit
row at all — contradicting the design's own INV-ISS0784-1.

**Root cause (traced through the real call chain):** `Scheduler.fire_timer/2` and
`ServiceTaskDispatcher.attempt_dispatch/2` each open their own outer
`Repo.transaction/1` and call `Engine.advance_after_timer_fired/3` /
`Engine.advance_after_service_task_outcome/4` from *inside* it, passing the literal
`Repo` module. `persist_timer_fired_advance/7` / `do_persist_service_task_advance/10`'s
own inline `{:error, _failed_step, reason, _changes}` clause then called
`record_task_activation_rejection_audit/5` — which opens its *own*
`Repo.transaction/1` — but since Ecto does not start a genuinely new DB-level
transaction for a nested `Repo.transaction/2` call on the same process, this "second,
independent" write was really still inside the caller's single still-open outer
transaction. Once that outer transaction rolled back (`fire_timer/2`'s own
`Repo.rollback(reason)`), the audit insert rolled back with it. Sites 1/2 never hit
this because `create/2`/`complete_task/3` open the *only* transaction on their call
path — there is no further-out caller holding one open around them.

**The fix (ELIXIR-DEV, commit `6c716637`):** the audit write was moved out of the two
inline clauses entirely, to the two outer callers —
`Scheduler.attempt_fire/2` (site 3) and
`ServiceTaskDispatcher.call_advance_after_service_task_outcome/3` (site 4) — which
issue it strictly *after* their own `Repo.transaction/1` has fully returned (and,
since we're in the error branch, already rolled back — a real, separate DB
transaction at that point). `record_task_activation_rejection_audit/5` was changed
from `defp` to `@doc false def` so both callers can reach it. Sites 1/2 were left
untouched — they were already correct.
