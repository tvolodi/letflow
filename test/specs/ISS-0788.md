# ISS-0788 — Regression Tests

## Issue

`render_upload_attachment/2` had no clause for `{:error, :storage_quota_exceeded}` or
`{:error, :tenant_not_found}`. Either return value from `Attachments.upload/2` caused a
`FunctionClauseError` crash (unhandled 500) instead of a caller-actionable 4xx.

Fix: added two new `render_upload_attachment/2` clauses in
`lib/letflow/routers/instances.ex` (commit `fb128f80`):
- `{:error, :storage_quota_exceeded}` → 409 Conflict, `"tenant storage quota has been reached"`
- `{:error, :tenant_not_found}` → 422 Unprocessable, `"request tenant does not exist"`

## Acceptance Criterion (AC3, route-level)

A route-level test drives both conditions through `POST /instances/:id/attachments` and
asserts a handled 4xx response, not a 500 (`FunctionClauseError`).

## Test Cases

Both tests live in `test/letflow/routers/instances_test.exs`,
describe `"ISS-0788 regression: unhandled upload/2 error atoms must not crash to 500"`,
tagged `@tag :iss_0788`.

### TC-1: over-quota upload → 409

**Why this test exists:** proves `render_upload_attachment/2`'s new
`:storage_quota_exceeded` clause fires at the route boundary, returning 409 rather than
crashing to a `FunctionClauseError` 500. The route layer had previously left this tag
unhandled despite `Attachments.upload/2`'s own `@spec` naming it.

**Setup:** provision a real tenant; set `storage_allowance_bytes = 1` so any upload
exceeds the quota. `Attachments.upload/2` returns `{:error, :storage_quota_exceeded}`.

**Assert:** `conn.status == 409`, `resp_body =~ "quota"`.

### TC-2: absent Tenant row → 422

**Why this test exists:** proves `render_upload_attachment/2`'s new `:tenant_not_found`
clause fires at the route boundary, returning 422 rather than crashing to a
`FunctionClauseError` 500.

**Setup:** provision a real tenant (creates schema + Tenant row + Registration row);
delete the Registration (tenant_schemas) row to satisfy FK constraints, then delete the
Tenant row. The physical schema still exists so `get_storage_usage` runs normally. The
Authorize plug resolves the schema name from the tenant_id via the pure
`schema_name_for_tenant/1` function (no DB lookup), so the request reaches
`Attachments.upload/2`. Inside `check_storage_quota/3`, `Repo.get(Tenant, tenant_id)`
returns `nil` → `{:error, :tenant_not_found}`.

**Assert:** `conn.status == 422`, `resp_body =~ "tenant"`.
