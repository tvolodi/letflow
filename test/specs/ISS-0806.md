## Requirement / acceptance criterion

AC1 — `defmanifest/1` raises a `CompileError` at macro-expansion time when any atom
appearing in a `role_grants` value list is not declared in `permissions`. The error
message names both the offending atom and the calling module. A manifest whose
`role_grants` atoms are all present in `permissions` compiles cleanly.

In `lib/letflow/modules/module.ex`, the `unless perm in permissions do raise CompileError … end` block
inside the `for` comprehension was replaced with `:ok` (a no-op):

```elixir
# MUTANT: compile-time check disabled — permission validation removed

  :ok
end
```

### Which test assertions fail under the mutant

## F3 race condition fix (REVIEWER finding)

REVIEWER flag F3 (step-03d-reviewer.json): two separate tests both compiled
`Letflow.Test.BadManifestModule` via `Code.compile_string(@bad_module_source)`.
With `async: true`, these could race: the second `Code.compile_string` call may
encounter the partially-registered module atom from the first, triggering an
unintended "redefining module" warning or a transient atom table collision.

**Fix applied:** `@bad_module_source` split into two distinct module attributes:

- `@bad_module_source_raises` — defines `Letflow.Test.BadManifestModule1`
- `@bad_module_source_names_caller` — defines `Letflow.Test.BadManifestModule2`

Each test now compiles a unique module name, eliminating the race. The `assert
error.description =~ "Letflow.Test.BadManifestModule2"` assertion in test 2 is
updated to match the new name. Semantics and coverage are unchanged.
