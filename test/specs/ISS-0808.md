# ISS-0808 — TenantStatus PLATFORM_ADMIN exemption: roles_from_strings normalization

**WF run:** WF03-ISS0808-20260925  
**Fix commit:** `97c50b5d`  
**Test file:** `test/letflow/plugs/tenant_status_test.exs` — `describe "ISS-0808 — PLATFORM_ADMIN check uses Authorization.roles_from_strings/1"`

---

## Root cause

`Letflow.Plugs.TenantStatus` performed the PLATFORM_ADMIN exemption check using a raw
string membership test against `conn.assigns[:auth_context][:roles]` (a `[String.t()]`
list). After `@platform_admin` was updated to the atom `:PLATFORM_ADMIN` (to share the
same type as `Authorization.roles_from_strings/1`'s output), comparing an atom to a
string list with Elixir's `in` operator always evaluates to `false` — `:PLATFORM_ADMIN
not in ["PLATFORM_ADMIN"]` is `true` — so every PLATFORM_ADMIN caller against an
`:inactive` tenant was incorrectly rejected with 403.

**Pre-fix code path (regression scenario):**
```elixir
# roles is the raw string list from auth_context
roles = raw_roles   # ["PLATFORM_ADMIN"] as delivered by JWT → AuthPipeline
# @platform_admin = :PLATFORM_ADMIN (atom, not string)
cond do
  tenant.status == :inactive and @platform_admin not in roles ->
    # :PLATFORM_ADMIN not in ["PLATFORM_ADMIN"]  →  true  (atom ≠ string)
    reject_inactive(conn)   # 403 — WRONG for PLATFORM_ADMIN
  ...
end
```

**Post-fix code path (correct):**
```elixir
raw_roles = get_in(conn.assigns, [:auth_context, :roles]) || []
roles = Authorization.roles_from_strings(raw_roles)
# roles_from_strings(["PLATFORM_ADMIN"]) → [:PLATFORM_ADMIN]
cond do
  tenant.status == :inactive and @platform_admin not in roles ->
    # :PLATFORM_ADMIN not in [:PLATFORM_ADMIN]  →  false  (exempt)
    conn   # pass-through — CORRECT
  ...
end
```

## Acceptance criteria

### AC-1: A PLATFORM_ADMIN caller (string role from JWT) is exempt from the :inactive 403

**Test:** `"a PLATFORM_ADMIN caller (string role) is exempt via roles_from_strings normalization"`

**Why this test exists:** The regression is specifically that an atom–string type mismatch
silently breaks exemption. The test injects `roles: ["PLATFORM_ADMIN"]` (a raw string, as
JWT → `AuthPipeline` produces) into `auth_context` and asserts `refute conn.halted` against
an `:inactive` tenant. This is the mechanically decisive test: if `roles_from_strings/1` is
removed (or bypassed), the atom `@platform_admin` can never be `in` a string list, so the
403 fires and `refute conn.halted` fails.

**Failure mechanism on pre-fix (mutant):**
- Mutant line: `roles = raw_roles` (instead of `roles = Authorization.roles_from_strings(raw_roles)`)
- `roles = ["PLATFORM_ADMIN"]`; `@platform_admin = :PLATFORM_ADMIN`
- `:PLATFORM_ADMIN not in ["PLATFORM_ADMIN"]` → `true` → `reject_inactive/1` fires → `conn.halted = true`
- `refute conn.halted` → **FAILS** ✗

**Pass on post-fix:**
- `roles_from_strings(["PLATFORM_ADMIN"])` → `[:PLATFORM_ADMIN]`
- `:PLATFORM_ADMIN not in [:PLATFORM_ADMIN]` → `false` → plug passes conn through
- `refute conn.halted` → **PASSES** ✓

---

### AC-2: A non-PLATFORM_ADMIN caller with a valid role is not exempt

**Test:** `"a non-PLATFORM_ADMIN caller is not exempt, even with valid roles"`

**Why this test exists:** Validates that the exemption is strictly role-gated — a caller
with a real but non-admin role (here `"PROCESS_OPERATOR"`) is still rejected. Provides
behavioral coverage for the non-admin rejection path regardless of the normalization step.

**Note on mutant sensitivity:** This test passes under both pre-fix and post-fix code
because non-admin actors are rejected in both paths (the atom `@platform_admin` is never
in a string-only list, so both raw and normalized paths reject non-admins equally). This
test does not serve as a standalone regression guard for ISS-0808, but it is valid
behavioral coverage.

---

### AC-3: An unrecognized role string that resembles an admin role is not exempt

**Test:** `"an unknown role string is not exempt (roles_from_strings/1 filters out unknown strings)"`

**Why this test exists:** Guards against future privilege escalation via unknown role
strings. `roles_from_strings/1` silently drops strings it doesn't recognize (returns `[]`
for all-unknown input). A string like `"PLATFORM_ADMIN_WANNABE"` must never match
`:PLATFORM_ADMIN`. Proves the filter behavior, not just the exemption path.

**Note on mutant sensitivity:** Same as AC-2 — the unrecognized string also fails the atom
comparison under the pre-fix path. This test does not fail under the regression scenario
but is correct behavioral coverage.
