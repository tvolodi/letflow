# Test spec: ISS-0883 — `entries/1` indent-tolerant matching + A11 indent-consistency assertion

Source: `docs/issues/ISS-0883.yaml`, `lib/letflow/design/iss0883-status-index-indent-check.md`.
Fix already implemented (ELIXIR-DEV, commit `cad6fcf2`) in
`test/support/status_history.ex` (`entries/1`) and
`test/docs/requirement_status_invariants_test.exs` (new assertion **A11**).

## The gap this spec closes

A9 and A11 in `test/docs/requirement_status_invariants_test.exs` only ever run against
the real, on-disk `docs/status/requirement_status.*.yaml` files, which are (and should
stay) well-formed. Nothing in the suite demonstrated that the fix actually *catches*
malformed input of PR #1972's real shape — only that well-formed input still parses
correctly. This is a false-negative-coverage gap: a regression in `entries/1`'s
indent-tolerance could ship silently because no test exercises it against a
deliberately malformed fixture.

New file: `test/support/status_history_test.exs` — a hermetic unit test file for
`Letflow.Test.StatusHistory.entries/1`, using a throwaway fixture file written to
`System.tmp_dir!/0` and removed via `on_exit`. Nothing in it touches `docs/status/` or
any real volume/index file.

## Fixture

One synthetic volume-shaped file, containing the file's real header/ROLL RULE/ENTRY
SCHEMA boilerplate (trimmed, but the same shape every real volume carries) plus two
`history:` entries:

- `REQ-001`, correctly indented at the documented 2-space `- req:` / 4-space field
  convention.
- `REQ-422`, at **0-space** `- req:` indent with its fields at 2-space — PR #1972's
  exact malformed shape, reproduced verbatim from the ISS-0883 design doc's "Worked
  example (concrete, using PR #1972's actual shape)" section.

## Test cases and why each exists

1. **"pre-fix regex would not have matched PR #1972's 0-indent line (confirms
   fail-first)"** — Directly runs the *old* item regex (`~r/^  - ([a-z][a-z0-9_]*): ?(.*)$/`,
   quoted verbatim from the design doc's "Root cause" section — hard-anchored to
   exactly 2 leading spaces) against the fixture's 0-indent line and asserts it does
   NOT match, and does match the 2-space sibling line for contrast. This is the
   fail-first proof: it shows by direct regex execution — not by assertion from memory
   — that this exact fixture is unrecognized by the pre-fix matcher, which is why
   `entries/1` pre-fix would have silently dropped `REQ-422` entirely (the false-green
   mechanism ISS-0883 fixes). This test does not call `entries/1` at all — it isolates
   the one regex line that changed.

2. **"entries/1 counts the 0-indent entry (false-green/miscounting half of ISS-0883
   fixed)"** — Asserts `entries/1` on the fixture returns both `REQ-001` and `REQ-422`,
   in order. This is the positive proof that the post-fix code recognizes the 0-indent
   entry at all — the fixed counterpart to test case 1's fail-first proof.

3. **"entries/1 records indent: 0 for the malformed entry, and 2 for the conforming
   one"** — Asserts the returned `indent:` value is exactly `0` for `REQ-422` and `2`
   for `REQ-001`. This exists because counting the entry is necessary but not
   sufficient: the design doc is explicit that `indent` must never be defaulted or
   normalized (no `Map.get(raw, :indent, 2)`), since that would silently hide the very
   case the fix exists to surface. This proves the real on-disk indent is threaded
   through, not coerced.

4. **"REQ-422's fields (event/agent/at/note) still attach correctly despite the
   0-indent item line"** — Asserts `event`, `agent`, `at`, and the field-order list are
   all correctly parsed for the malformed entry. This exists because the fix's field
   regex accepts a field line only when its indent is exactly `current.indent + 2` (a
   *relative*, not absolute, rule) — this test proves that relative rule actually
   re-associates a uniformly-shifted entry's fields, not just its item line.

5. **"A11's own indent-violation predicate (indent != 2), reused verbatim, flags only
   the malformed entry"** — Applies A11's exact filter (`Enum.filter(&(&1.indent != 2))`,
   copied from `test/docs/requirement_status_invariants_test.exs`, not reimplemented)
   to the fixture's entries and asserts it flags exactly `{line, 0, "REQ-422"}` and
   nothing for `REQ-001`. This is the direct unit-level proof that A11's logic, applied
   to a controlled fixture with a known-bad and a known-good entry side by side,
   discriminates correctly — something the real-files-only A11 test block can never
   demonstrate (every real entry is already correctly indented).

## Fail-first verification

Test case 1 is itself the fail-first demonstration, run for real against the shipped
pre-fix regex text (not the live `entries/1`, since that function is already fixed on
this branch — reverting it would require checking out the pre-fix commit, which
design doc + issue history already document exhaustively). Test cases 2–5 are the
post-fix passing counterpart, run for real via `mix test` against the current code (see
run output below).
