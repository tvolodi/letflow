# ISS-0926 test spec: SERVICE_TASK `body_template` is rendered by the engine (Q-926, GH-2106)

Design: `lib/letflow/design/iss0926-service-task-body-template-rendering.md` (sections 1, 2, 3, 6).
Implementation under test: `Letflow.Engine.ServiceTask.render_body_template/2` and siblings,
`Letflow.Engine` activation sites, `Letflow.Engine.ServiceTaskDispatcher` (`resolve_dispatch_body/1`),
plus fixture v1.3 of the Meridian "Regulatory Compliance Review" definition.

Defect: the engine froze the RAW `body_template` into `config_snapshot` and the dispatcher sent it
unrendered, so `{{variables.X}}` went out literally to a third party (the BaFin notice) and the
regulatory-notice `reason` (UAT EO-002 `sla_breach_30_days`) could not be produced per path.

## Acceptance criteria and proving tests

Criteria are those of the issue and design (section 7): the body is rendered once at activation and
frozen; the dispatcher sends the frozen rendered body; values cannot alter JSON structure; typed,
non-leaking failures; legacy rows are handled; the two regulatory notices carry distinct literal reasons.

| AC | Test(s) | Why this test exists |
|---|---|---|
| AC1 body rendered at activation and frozen in `config_snapshot["rendered_body"]` (inline) | wiring I-1, I-1b, I-5, I-1c; unit T-R1..T-R3d | I-1 is THE regression: pre-fix the key is absent and the snapshot holds the raw text. I-1b/I-5 pin the static and nil cases (key always present, `nil` for no template). I-1c proves the completion hop renders against the MERGED task output variables, not the stale start variables |
| AC2 catalog path renders the same node attribute | catalog I-3 (4 tests); `@inline_keys` key-set test (T9) | `body_template` is a NODE attribute on both routes; one render step must cover both. Precedence: a catalog resolution error wins over a body error |
| AC3 dispatcher sends the rendered body, never the raw template | dispatcher I-2, I-2b (inline and catalog branch), I-11; wiring I-2, I-4b | I-2/I-2b give the snapshot a raw template and a DIFFERENT rendered body, so only the rendered one can satisfy the assertion. I-11: a retry (HTTP 429) resends the identical frozen body |
| AC4 value escaping / no structure injection | unit T-R4, T-R4b, T-R5, T-R6, T-R7a..T-R7f (property), T-R14; wiring I-4a, I-4b; catalog injection test | Each Jason guarantee in design 2.3 has its own row (quote, backslash, controls with UPPERCASE hex, U+2028/9 as six ASCII chars, `/` NOT escaped, DEL, `<>&`, UTF-8 text). I-4b proves it end to end on the wire: the received body decodes to exactly the template's keys |
| AC5 placeholder must be inside a JSON string (reject otherwise) | unit T-R11, T-R12, T-R21a..c; wiring I-6b | The scan is the only place that decides position; T-R11 proves the value is never consulted, T-R12 the escape-flag handling, T-R21b "first inside, second outside" |
| AC6 missing / nil / typed variables | unit T-R8, T-R9, T-R10, T-R16; wiring I-6a | Absent key = typed error (an empty `review_id` on a regulatory filing is worse than a visible failure); present nil = empty string |
| AC7 decodability and size cap | unit T-R13 (exact limit and +1), T-R15, T-R2b, T-R2 | Zero-placeholder templates stay byte-identical to pre-fix (no new failure mode): T-R2/T-R2b |
| AC8 typed, non-leaking errors | unit T-R18, T-R19, T-R20; wiring I-6c, I-7 (`reason`/`details` surface checked for a planted secret) | Fixed sentences, only the atom class persisted |

T13: both shipped templates are renderable.
