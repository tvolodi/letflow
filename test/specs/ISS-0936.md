# Test Spec: ISS-0936 — `uat_preflight.sh` reports NO_PASSWORD because the `qa-uat-env` source prints a BARE JWT

**Issue:** ISS-0936 (queue Q-919, GH#2070). **Design:**
`lib/letflow/design/iss0936-uat-preflight-bare-jwt.md` (section 6).
**Fix:** `scripts/uat_preflight.sh` — new `parse_token_line` helper used by `fetch_credential`'s
`qa-uat-env` branch (accepts `Token: <jwt>` or a bare `eyJ...` JWT line; ignores noise).
**Test file:** `test/scripts/uat_preflight_bare_jwt_test.exs` (ExUnit, run by `mix test`).

## Criterion

1. A bare JWT line on the credential source's stdout is accepted (login reaches verification).
2. The labelled `Token: <jwt>` form still works.
3. Noise lines (warnings, banners, hostnames, short lookalikes) are NOT mistaken for a token.
4. The token is never echoed to stdout/stderr or the `--out` JSON.

## Shape of the tests

Every test shells out to the real script (`System.cmd` of `bash scripts/uat_preflight.sh`) with a
fake `cred.sh` source written per test, one scenario fixture, `--sha deadbeef`, and `--idp-url`
equal to `--base-url` so no DNS/HTTPS happens (hermetic). Launcher: `UAT_PF_BASH` else `bash` on
PATH (Windows devs must export `UAT_PF_BASH` to git-bash; the shared `run_preflight/2` fails with
that hint if the report header is absent). T1-T6 use an unreachable URL (`127.0.0.1:9`), so a
parsed token ends as `BAD_CRED` ("reached verification") and an unparsed one as `NO_PASSWORD`.
T7 uses an in-test `:gen_tcp` stub answering every GET 200 `{}`, so a parsed token ends `OK`.
Assertions are on output text, not exit code (the run is ENV_NOT_READY by design).

| Test | Why it exists (not just a restatement) |
|---|---|
| T1 noise line then bare JWT | The exact real-world shape (`qa-uat-env.sh` prints a bare JWT, possibly after warnings). Core regression: pre-fix every login was NO_PASSWORD. |
| T2 `Token: <jwt>` | Backward-compat guard: the labelled form must keep working. Catches a fix that replaces rather than extends. |
| T3 noise only | Proves acceptance is selective: no token means NO_PASSWORD and no login attempt. Catches "accept any line". |
| T4 dotted non-JWT lines | Four inputs, each defeating a different weakness: `auth.qa.bizdala.com` / `qa.bizdala.com` (the real hostname noise), a >= 40 char 3-segment hostname without `eyJ` (kills a dropped-prefix mutant, since the length floor alone would otherwise hide it), and a short `eyJh.a.b` (kills a dropped-length-floor mutant). |
| T5 CRLF-terminated bare JWT | git-bash/Windows sources emit CRLF; end-to-end guard. |
| T5b JWT surrounded by spaces | The only test that really exercises the `strip()` (universal newlines already removes CRLF, so T5 cannot). |
| T6 no secret echo | Invariant 4. Asserts the full token and its first segment are absent from output and `--out` JSON, and first asserts the token WAS consumed (BAD_CRED) so it cannot pass vacuously. |
| T7 end to end vs stub API | Proves the parsed bare JWT is actually sent and verified (`=OK`, no `login failed`), not merely recognised. |

Note: test names are part of the `tmp_dir` path which the script prints in its report, so names
must not contain the forbidden substrings `NO_PASSWORD` / `BAD_CRED` (found the hard way: T1's
first draft name failed its own `refute`).

## Fail-first against pre-fix code (verified, not asserted)

Run in a throwaway `git worktree` of `origin/main` (script without `parse_token_line`) plus the new
test file: **3/8 passed, 5 failed: T1, T5, T5b, T6, T7** (T6 fails on its non-vacuity guard; T2,
T3, T4 pass pre-fix as expected, they are guards). Post-fix: **8/8 pass**.
