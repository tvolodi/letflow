# ISS-0993 / ISS-0994 -- PR A1 test spec (platform scope separation, shadow mode)

Design (governs): `lib/letflow/design/iss0993-platform-scope-separation.md` -- sections 11 (guards), 12 (test list), 13 (PR A1).
Scope of this spec: the tests the design assigns to A1: items 1-4, 6, 11-14, 17 (except 17(0), A2), 18, and the A1
variants of 5, 7, 8, 19 and 20, plus the `test/support` fixture helper. In A1 the LEGACY outcome is enforced
(`Letflow.Plugs.Authorize` forces `platform_tenant?: true`) and a shadow line
`platform_scope_shadow_deny key=<PolicyKey> platform_tenant=<boolean>` is logged when the real decision would differ.
Every assertion marked "legacy" flips in A2 (the design says where).

Why each group exists is stated per row; the criterion is the design item, not a restatement of it.

## Fixture

`test/support/platform_tenant_fixture.ex` (`Letflow.Support.PlatformTenantFixture`): pin/unpin the platform tenant through
`Application.put_env` with an `on_exit` restore (`pin!/1`, `unpin!/0`, `with_platform_tenant!/2`), three provisioned tenants
P / A / B (`three_tenants!/0`, built on `Letflow.TenantFixture`), hand-assigned `auth_context` router connections, real API
tokens plus a full-`Letflow.Router` request builder, and `shadow_lines/1`. Every module using it is `async: false`.

## Not in A1 (and why)

Items 9 and 10 (TenantStatus, role escalation: A2), item 15 (existing fixtures; the
implementation edited three suites), item 16 (full `mix test`, TEST-RUNNER), G4, 17(0), the A2 enforcing variants of 5/7/8/19/20,
and `POST /onboarding` with a body `id` (`Identity.create_tenant/1`, which onboarding calls, is covered in 17(e)).
No `git ls-files` guard is written: the pin is a non-secret UUID, so the "no 64-hex literal" guard is not applicable; the source
scans read `lib/` working-tree files, which equal the tracked files in CI.
