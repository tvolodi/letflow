## Observation (not a defect, recorded for the reviewer)

`H1` refuses only callers WITHOUT platform scope. The platform operator can therefore still create a `process_routing_role` whose
name is a case/whitespace variant of `PLATFORM_ADMIN` (observed: 200 for `platform_admin`, ` platform_admin `, `Platform_Admin`).
Such a role is inert for authorization (the parser matches the exact literal only and `platform_role` rejects variants with 422),
and `POST /roles` is operator-or-designer scope, so nothing is escalated; REQ-447 plans to reject the name outright in
non-platform tenants. Tests pin the actual behaviour (the variants are never accepted as a `platform_role`).
