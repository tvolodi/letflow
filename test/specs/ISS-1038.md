# ISS-1038 / Q-1039 -- deterministic, attributable log capture in tests, test spec

Run: `WF03-LOGCAPTURE-20261008`. Code under test: the test-support module
`Letflow.Test.LoggerCollector` (`test/support/logger_collector.ex`) and its two users.
Tests: `test/letflow/test_support/logger_collector_test.exs` (new, `async: false`: the handler
touches the VM-global primary translator filter), `test/letflow/api/authz_deny_log_test.exs`,
`test/letflow/login_discovery/notifier_no_leak_test.exs` (both migrated off `capture_log`).

## Problem

`ExUnit.CaptureLog.capture_log/1` is a GLOBAL Logger capture. Under concurrent tests it receives
events from unrelated processes: `no leak: untrusted_implicit` failed in CI because its capture held
an error-level `alert delivery exhausted` event (`lib/letflow/obs/alerts.ex`, metadata
`component: "alert_delivery"`) logged by another test's alert deliverer, and `AuthzDenyLogTest` once
lost a line. Fix: a private SYNCHRONOUS `:logger` handler (runs in the emitting process, `send/2`s before
the log call returns) that forwards only events attributable to the test: emitted by the test process,
by a process with the test in `$callers` (Task / Task.Supervisor) or `$ancestors` (`:proc_lib`), or by
a registered process listed in `also_from`.

## Test map

| Item | Test | Why it exists |
|---|---|---|
| attribution excludes the unrelated event | `logger_collector_test`: "attributed collector: the own event is present, the unrelated one is not" | the flake reproduced inside one window with message synchronisation (no sleeps): an own event from a `Task.Supervisor` child plus an unrelated `Logger.error("alert delivery exhausted", component: "alert_delivery")` from a plain spawned process; only the own one is collected |
| the old style really flakes | "the OLD capture_log style DOES contain the unrelated line (the observed flake)" | proves the injection is a faithful reproduction: `capture_log` over the same window contains the unrelated line, so `errors == []` / `refute` over it fails |
| opt-out is the old behaviour | "attribute_to: nil collects both events" | default `attribute_to` collects everything (contract of the pre-existing API) |
| supervisor-emitted reports | "also_from picks up an event emitted by a registered process, and only when listed" | the TaskSupervisor itself emits the child-terminated report on a brutal kill; listed names are attributed, unlisted are not |
| existing contract | "default options keep the REQ-441 contract..."; "sasl: false leaves the translator filter untouched; raw: false yields the bare message" | SASL forcing and `formatted <> "\n" <> inspect(event)` text are the no-leak suite's contract; restoration of the translator filter on `detach/1` |
| no vacuous absence | "assert_alive!/1 fails loudly when the handler was removed" | `:logger` removes a crashed handler; absence assertions would then pass vacuously |
| `authz_deny_log_test` | all `sink_log/1` users | `sink_log/1` now uses the shared collector (`attribute_to: self()`, `sasl: false`, `raw: false`), keeps the text filter on `authz_deny` / `authz deny log` and the handler-alive guard; the local `Sink` module is removed |
| `notifier_no_leak_test` | all; probe test "the sink is live and attributing..." | `capture_log` removed; sink attributed to the test plus `Letflow.LoginDiscovery.TaskSupervisor` (every other test touching it is `async: false`); the probe proves own-process and Task.Supervisor-child lines arrive and an unrelated spawned process's `alert delivery exhausted unrelated` does not |

`H.debug_logging!()` in the no-leak `setup` is unchanged (it sets/restores the global level so debug lines are emitted at all); no new global level change is introduced.
