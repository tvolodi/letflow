# ISS-1038 / Q-1039 -- deterministic, attributable log capture in tests, test spec

Run: `WF03-LOGCAPTURE-20261008`. Code under test: the test-support module
`Letflow.Test.LoggerCollector` (`test/support/logger_collector.ex`) and its two users.
Tests: `test/letflow/test_support/logger_collector_test.exs` (new, `async: false`: the handler
touches the VM-global primary translator filter), `test/letflow/api/authz_deny_log_test.exs`,
`test/letflow/login_discovery/notifier_no_leak_test.exs` (both migrated off `capture_log`).

## Problem

`ExUnit.CaptureLog.capture_log/1` is a GLOBAL Logger capture. Under concurrent tests it receives
events from unrelated processes: `no leak: untrusted_implicit` failed in CI because its capture held
an error-level `alert delivery exhausted` event (`lib/letflow/obs/alerts.ex`, metadata
`component: "alert_delivery"`) logged by another test's alert deliverer, and `AuthzDenyLogTest` once
lost a line. Fix: a private SYNCHRONOUS `:logger` handler (runs in the emitting process, `send/2`s before
the log call returns) that forwards only events attributable to the test: emitted by the test process,
by a process with the test in `$callers` (Task / Task.Supervisor) or `$ancestors` (`:proc_lib`), or by
a registered process listed in `also_from`.

## Attribution narrowing (decided, recorded)

The attributed sink observes only events from the test process, its `$callers` / `$ancestors`, and
the registered names in `also_from`. Events from processes NOT linked to the test (e.g. `:ssl`
connection helpers or `gen_smtp` internals not started through the test's call chain) are not
observed, so the unique-marker leak scan in `notifier_no_leak_test` covers ATTRIBUTED events only.
Decision (ORCH): no unattributed global scan -- that is exactly the hazard class being removed (other
tests' events making this one flake). Partial mitigation: the M2b "no surviving process" check in the
same file proves the SMTP call leaves nothing behind that could log later. `also_from` for the
notifier TaskSupervisor is safe only because every other test touching it is `async: false`.

### (b) NOT CONVERTED, with justification

capture runs synchronously in the test process AND the assertion is keyed to a unique token or the
query text of the test's own data (or is presence-only, which extra foreign lines cannot falsify).
Residual risk, stated honestly: a leftover DETACHED task started by an earlier module that is still
running and logs the same token (practically impossible for a unique marker; the one real exposure is
the unkeyed counts below). This residual gap is accepted, not claimed closed.
