# Test Spec: REQ-067 — `Letflow.Api.Pagination`

**Requirement:** REQ-067 (stage S4) — port `src/api/pagination.zig` (406 lines,
R-Co's API-06) as the shared cursor encode/decode, prefix validation, expiry
checking, page-size validation, and standardised page response every S4 list
endpoint delegates to.
**Test tier:** unit (pure module — no `Plug.Conn`, no `Ecto.Repo`).
**Design:** `lib/letflow/design/api-pagination.md`.
**Test file:** `test/letflow/api/pagination_test.exs`.

## 0. Scope test (WF-02 Step 3)

**IN SCOPE — the answer is YES.** `lib/letflow/api/pagination.ex` (332 lines) is
real application-executable Elixir: a struct, twelve public functions, and private

## 1. Why each test case exists

### AC1 — constants ported exactly, asserted via accessor, not literal duplication

*"Port the constants exactly: MAX_PAGE_SIZE 200, DEFAULT_PAGE_SIZE 50,
MIN_PAGE_SIZE 1, CURSOR_EXPIRY_US 86_400_000_000."*

1. `max_page_size/0 returns 200`
2. `default_page_size/0 returns 50`
3. `min_page_size/0 returns 1`
4. `cursor_expiry_us/0 returns 86_400_000_000`

Each asserts the accessor function's return value against the literal from the
requirement text, independently of any behavior that happens to depend on it
(design §1: "the constant and the behavior that depends on it are checked
independently"). This exists because a test that only checked
`validate_page_size(201) == {:error, ...}` would still pass if `@max_page_size`
were silently changed to some other value the boundary tests didn't happen to probe
— asserting the accessor directly pins the literal itself.

### AC2 — page-size validation: reject, not clamp; non-numeric rejected at parse layer

*"A requested page size above MAX_PAGE_SIZE, below MIN_PAGE_SIZE, or non-numeric is
a 400, not a silent clamp."*

`parse_page_size_param/1` (parse-time, string input):

5. `parse_page_size_param(nil) is {:ok, nil}` — absent param defaults later.
6. `parse_page_size_param("50") is {:ok, 50}` — ordinary numeric string.
7. `parse_page_size_param("abc") is {:error, :invalid_page_size}` — the
   non-numeric case AC2 names explicitly.
8. `parse_page_size_param("20x") is {:error, :invalid_page_size}` — trailing
   garbage after digits; `Integer.parse/1` alone would return `{20, "x"}` and a
   naive `elem(_, 0)` extraction would silently accept this. This case exists
   specifically to catch that implementation mistake.
9. `parse_page_size_param("3.5") is {:error, :invalid_page_size}` — a decimal
   point is non-numeric for this purpose.
10. `parse_page_size_param("-5") is {:error, :invalid_page_size}` — a negative
    sign parses fine via `Integer.parse/1` but must still be rejected (design
    §3: "the parsed integer is non-negative").

`validate_page_size/1` (range-time, already-parsed integer or nil):

11. `validate_page_size(nil) is {:ok, 50}` — default substitution.
12. `validate_page_size(0) is {:error, :page_size_too_large}` — the "below
    MIN_PAGE_SIZE" case AC2 names; ported verbatim under the single Zig error atom
    (design §0.2), not a separate `:page_size_too_small`.
13. `validate_page_size(201) is {:error, :page_size_too_large}` — the "above
    MAX_PAGE_SIZE" case, one past the boundary.
14. `validate_page_size(1) is {:ok, 1}` — the MIN_PAGE_SIZE boundary itself
    succeeds (reject is for *below* the minimum, not at it).
15. `validate_page_size(200) is {:ok, 200}` — the MAX_PAGE_SIZE boundary itself
    succeeds. Cases 12-15 together pin the exact fence-post: 0 rejected, 1
    accepted, 200 accepted, 201 rejected — a clamp implementation (`min(size,
    200)`) would make case 13 return `{:ok, 200}` instead of an error, so this is
    genuinely falsifiable against "reject, not clamp."

### AC3 — cross-endpoint prefix rejection

*"A cursor carries a type prefix so a cursor minted by one endpoint cannot be
replayed against another."*

16. `decode_cursor rejects a cursor minted with a different prefix` — builds a raw
    cursor with prefix `"T:"` (task-list), encodes it, then calls
    `decode_cursor/4` with prefix `"I:"` (instance-list); asserts
    `{:error, :wrong_endpoint}`. This is the literal AC3 scenario: a cursor minted
    by one endpoint, replayed against another endpoint's `decode_cursor/4` call.
17. `decode_cursor accepts a cursor decoded with its own prefix` — the same raw
    cursor decoded with `"T:"` succeeds, proving case 16 fails for the *prefix
    mismatch* reason and not because the cursor is malformed in some other way.
18. `decode_cursor rejects a cursor shorter than the prefix` — a decoded payload
    that doesn't even reach the prefix's byte length; guards the
    `byte_size(decoded) >= byte_size(prefix)` branch specifically (design's
    `check_prefix/2`), not just the `String.starts_with?/2` branch.

### AC4 — expiry checking, no wall-clock waiting

*"An expired cursor is rejected."*

19. `decode_cursor rejects a cursor built with a deliberately old timestamp` —
    builds a raw cursor via `build_raw_cursor/3` with `timestamp_us` fixed at `0`
    (the Unix epoch, unconditionally more than 24h in the past relative to any
    real clock read), encodes it, decodes with the **default** `expiry_window_us`
    (omitting the 4th argument), and asserts `{:error, :expired}`. No
    `Process.sleep/1`, no `DateTime` manipulation of the running clock — the
    "old" timestamp is a plain integer literal baked into the cursor payload
    itself, per the handoff's explicit instruction.
20. `decode_cursor accepts a cursor within the expiry window` — builds a raw
    cursor with `timestamp_us` set to `System.system_time(:microsecond)` (now),
    decodes immediately, asserts success. This is read once at test time, not
    slept on, and exists so case 19 is shown to fail for *staleness*, not because
    every cursor this test builds is broken.
21. `decode_cursor honours a custom expiry_window_us narrower than the default` —
    builds a cursor with `timestamp_us` a few seconds in the past (via
    `System.system_time(:microsecond) - 5_000_000`), decodes with an explicit
    `expiry_window_us` of `1_000_000` (1s, deliberately narrower than that gap),
    asserts `{:error, :expired}`. This proves the 4th argument is genuinely
    read and not ignored in favor of the hardcoded default — case 19 alone
    (which omits the argument) would not catch an implementation that silently
    ignored an explicit override.

### AC5 — INV-1/INV-5, tenant isolation is structural, not conventional

*"the decoded cursor struct must have no tenant/schema field... A cursor minted
in tenant A and replayed against tenant B must return tenant B's page or an
error, never tenant A's rows."*

This is the security-load-bearing case (design §0.3).

22. `Cursor's struct fields are exactly [:inner]` — `%Cursor{} |> Map.from_struct()
    |> Map.keys()` asserted `== [:inner]`. Structural, not a documentation read:
    if a future edit added a `:tenant_id` field to the struct, this is the test
    that fails, independent of whether any code path happens to populate it yet.
23. `a cursor minted while iterating tenant A cannot surface tenant A's rows when
    decoded and scoped to tenant B` — the concrete replay scenario:
    - A fixture in-memory "store" is defined **in the test file only**
      (`fixture_rows/0`, a small list of `%{tenant: :a | :b, id: ..., name: ...}`
      maps) and a fixture `fixture_list(tenant_scope, cursor)` function that
      filters that list by `tenant_scope` — a parameter supplied **independently
      of the cursor**, standing in for "this endpoint's own request-context
      scoping" (REQ-072, not yet implemented). This fixture is not application
      code; it exists solely to give the property something concrete to violate
      against.
    - The test builds a raw cursor via `build_raw_cursor/3` using one of tenant
      A's row ids as the cursor `key`, encodes it, and decodes it via
      `decode_cursor/4` — this **succeeds regardless of which tenant "produced"
      it**, because `decode_cursor/4` has no tenant concept at all (design §0.3).
    - The decoded cursor is then handed to `fixture_list(:tenant_b, cursor)`.
    - Assertion: every row `fixture_list/2` returns has `tenant: :tenant_b`, and
      **none** has `tenant: :tenant_a` — even though the cursor's own `inner`
      payload was built from tenant A's data. This is falsifiable: a fixture
      that (wrongly) tried to parse a tenant id out of `cursor.inner` would find
      none there (there is nothing to find — the struct has one field, `inner`,
      and `inner` itself contains no tenant marker, only `<prefix><ts>:<key>`),
      so any such attempt necessarily falls through to `tenant_scope` alone,
      which is the point: **the cursor structurally cannot carry tenant A's
      identity across to influence a tenant-B-scoped lookup.**
    - A second assertion drives the same decoded cursor through
      `fixture_list(:tenant_a, cursor)` and confirms it returns tenant A's rows
      — proving the fixture is a real, functioning scoped lookup (not one that
      always returns empty, which would make the tenant-B assertion vacuous).

    This directly satisfies the handoff's requirement (task.description case 5):
    confirm the field set by reflection, then construct the fixture
    store/replay scenario and assert the isolation property concretely.

### AC6 — pagination completeness: no dup, no gap across 3+ pages

*"Paging through more rows than one page holds must return every row exactly
once with no duplicate and no gap across at least three successive pages."*

24. `paging through 3+ pages returns every row exactly once, no dup, no gap` —
    builds an in-memory list of 25 rows (each with a strictly monotonic integer
    `sort_key`), pages through it with a fixture pager using `page_size = 10`
    (3 pages: 10 + 10 + 5), where each page's `next_cursor` is built via
    `build_raw_cursor/3` from the last row's `sort_key`, encoded, and decoded
    via `decode_cursor/4` before the next page call reads its `key` back out via
    `parse_int_from_cursor/3` — round-tripping through this module's real
    encode/decode functions rather than passing the raw sort key between pages
    directly, so the test actually exercises the module under test, not just the
    fixture's own bookkeeping. Asserts: total items returned across all pages ==
    25; the multiset of returned ids has no duplicate (`Enum.uniq/1` unchanged
    length); the sorted returned ids equal the sorted original ids exactly
    (no gap).
25. `the final page reports no next_cursor` — the pager stops when a page's
    result is smaller than `page_size`; the fixture asserts `next_cursor == nil`
    only on the last of the three pages, guarding against an off-by-one that
    would silently fetch a phantom fourth, empty page whose absence case 24
    alone would not distinguish from "read exactly enough."

### Round-trip and encode/decode edge cases (design §4/§5, not tied to a single AC)

26. `encode_cursor/decode_cursor round-trip preserves inner exactly` —
    `decode_cursor(encode_cursor(raw), prefix, offset).inner == raw` for a raw
    payload built via `build_raw_cursor/3`. This is the round-trip fidelity §10
    names as this module's own contribution to AC6.
27. `decode_cursor rejects invalid base64` — a string containing characters
    outside the URL-safe base64 alphabet (e.g. `"not valid base64!!"`) yields
    `{:error, :invalid_base64}`.
28. `decode_cursor rejects a cursor with a malformed timestamp slice` — a raw
    cursor built by hand with non-digit bytes at the timestamp offset (e.g.
    `"T:abc:key1"`) yields `{:error, :invalid_cursor}`, not a crash and not
    `:invalid_base64` (design §5's deliberate atom split).
29. `decode_cursor rejects when expiry_ts_offset is past the end of the decoded
    payload` — `expiry_ts_offset >= byte_size(decoded)` yields
    `{:error, :invalid_cursor}`.

### `parse_int_from_cursor/3` and `find_nth_colon/2` edge cases

30. `parse_int_from_cursor extracts an in-bounds integer` — the ordinary success
    case.
31. `parse_int_from_cursor rejects an out-of-bounds offset/len` —
    `offset + len > byte_size(decoded)` yields `{:error, :invalid_cursor}`.
32. `parse_int_from_cursor rejects a non-digit slice` — a slice containing
    non-digit bytes yields `{:error, :invalid_cursor}` rather than a raised
    exception (INV-8: no crash on well-typed but semantically bad input).
33. `find_nth_colon finds the n-th colon 1-indexed` — a payload with 3 colons;
    asserts `find_nth_colon/2` for `n = 1, 2, 3` returns the correct byte offsets.
34. `find_nth_colon returns nil when fewer than n colons exist` — e.g. `n = 5`
    against a payload with only 2 colons.

### `build_raw_cursor/3` and `build_raw_cursor_timestamp_key/4` exact output format

35. `build_raw_cursor produces "<prefix><timestamp_us>:<key>"` — asserts the
    literal formatted string for a representative input, matching the design's
    §6 example exactly (`"T:1716412800000000:abc123"`).
36. `build_raw_cursor_timestamp_key produces "<prefix><ts>:<key>:<created_at>"` —
    same, matching the design's `"I:1716412800000000:abc123:1716412860000000"`
    example.

### `page_response/2`

37. `page_response/2 sets count to length(items), independent of caller input` —
    there is no separately-suppliable `count` parameter to disagree with
    `items`, so this asserts `count == length(items)` for a representative list
    and that `next_cursor` passes through unchanged.

## 2. Determinism

No test reads the wall clock into an assertion's *expected* value — cases 19-21
seed a fixed-old or fixed-recent timestamp literal or a fresh
`System.system_time(:microsecond)` read once and used immediately in the same
test (never slept on, never compared against a second later read). No
`:rand`, no `Ecto.UUID.generate/0`. All fixture data (rows, ids, tenants) are
literal, non-shared per-test constructs — no module-level mutable state, no
cross-test ordering dependency. `async: true`.
