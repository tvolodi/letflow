# Test spec: REQ-152 — Deny all four ambient Lua time sources; implement `platform.now()` (LUA-14 restated)

**Requirement:** REQ-152 (`docs/requirements.yaml`)
**Implementation:** `lib/letflow/engine/lua/sandbox.ex` (extended), `lib/letflow/engine/lua/platform.ex` (new)
**Design:** `lib/letflow/design/req152-lua-time-denial.md`
**Test code:** `test/letflow/engine/lua/sandbox_test.exs` (extended), `test/letflow/engine/lua/platform_test.exs` (new)

All script-visible assertions construct their `Lua.t()` exclusively via
`Letflow.Engine.Lua.Sandbox.new/0` — never `Lua.new/1` directly, never
`Letflow.Engine.Lua.Platform.install/1` called by hand — so every assertion exercises
the real production composition path: `platform.now` is reachable from a script only
because `Sandbox.new/1` calls `Platform.install/1` itself as part of construction.

## Empirical note carried over from REQ-151

Per `test/specs/REQ-151.md`'s empirical note (re-verified for the five new deny-set
entries): every path in the deny-set, once passed to `Lua.new/1`'s `sandboxed:` option,
becomes a real raising function when *called* (`Lua.sandbox/2` always writes a raising
callable). All eleven `os` functions are installed by the underlying library (`os.ex`
implements `clock`, `date`, `difftime`, `exit`, `getenv`, `setlocale`, `time`,
`time_ms`, `time_us`, `tmpname` — no `execute`), so `os.execute` is the sole vacuous
case among the eleven and still raises when called (`Lua.sandbox/2` writes a raiser at
the path regardless of whether the library itself installed anything there). Every
per-function test below therefore calls the function and asserts a raise, matching
AC1/AC3's "nil or raises" wording against the runtime's actual observed behavior for
every path in this requirement's scope.

## Test cases

### 1. The four ambient time sources named by AC1 (LUA-14's own criterion, extended)

**Why these tests exist:** AC1 is REQ-152's central acceptance criterion — LUA-14's own
literal `os.time` criterion, extended to `os.date`/`os.clock`/`os.difftime` as a
deliberate intent extension. Without a test calling each of the four from inside a real
`Sandbox.new/0` VM, the deny-set entries added in `sandbox.ex` (§2.2 of the design) are
unverified — a typo in a path atom (e.g. `[:os, :Time]`) or an entry accidentally
dropped during a future edit would silently leave the function reachable, and nothing
short of an actual VM evaluation would catch it.

- `os.time()` raises `Lua.RuntimeException` matching `/sandboxed/`.
- `os.date()` raises.
- `os.clock()` raises.
- `os.difftime(0, 0)` raises.

### 2. Default denials still hold after the extension (AC2, the `:sandboxed`-replaces-defaults trap)

**Why this test exists:** this is the requirement's own explicitly-named regression
guard. REQ-152's most likely wrong implementation is calling `Lua.sandbox(lua, [:os,
:time])` as a point-fix on top of an already-constructed VM, or constructing a second,
partial `Lua.new(sandboxed: [...])` list elsewhere — either of which would silently
re-open every one of REQ-151's 28 original denials (including `os.execute` and `load`)
because `Lua.new/1`'s `sandboxed:` option is not merged with the library's own
defaults; whatever list is passed IS the complete set. A test that only checks the four
*new* denials would pass even if the fix used the wrong mechanism and broke the
original 28. This test re-runs REQ-151's own trap-guard assertions (`os.execute`,
`load`, via both `Sandbox.new/0` and `Sandbox.new/1` with arbitrary opts) against the
post-REQ-152 33-entry list, so a regression in either direction is caught.

- `os.execute('ls')` still raises via `Sandbox.new/0`.
- `load('return 1')` still raises via `Sandbox.new/0`.
- Both still raise via `Sandbox.new/1` with arbitrary, requirement-irrelevant opts
  (proving the full list is used regardless of what's passed in `opts`).

### 3. The remaining seven `os` functions, completing all eleven (AC3)

**Why this test exists:** AC3 requires all eleven Lua 5.3 `os` functions proven
unreachable, combined across AC1 (four time functions) and AC3 (seven others). Six of
the seven (`os.execute`, `os.exit`, `os.getenv`, `os.remove`, `os.rename`,
`os.tmpname`) are REQ-151's pre-existing entries, re-tested here so REQ-152's suite is a
complete, self-contained proof of "all eleven" rather than depending on a reader to
cross-reference REQ-151's separate test file for the other six. `os.setlocale` is
REQ-152's own gap-closure addition (design §2.2 row 5, OQ-1) — REQ-151's implemented
deny-set did not actually include it despite REQ-151's description text claiming
otherwise, so this is the first test in the codebase to prove `os.setlocale` is denied
at all.

- `os.exit()`, `os.getenv('HOME')`, `os.remove('/tmp/x')`, `os.rename('/tmp/x',
  '/tmp/y')`, `os.setlocale('C')`, `os.tmpname()`, `os.execute('ls')` — each raises.

Combined with §1's four, all eleven Lua 5.3 `os` functions (`clock`, `date`,
`difftime`, `execute`, `exit`, `getenv`, `remove`, `rename`, `setlocale`, `time`,
`tmpname`) are proven unreachable by this file's tests alone.

### 4. `platform.now()` returns a `DateTime.from_iso8601/1`-parseable UTC string (AC4)

**Why this test exists:** AC4 is the positive half of this requirement — LUA-14 also
requires `platform.now()` actually work, not just that ambient sources are denied. A
test that only checked denial and never called `platform.now()` would leave a script
with no way to read time at all, silently failing every process using `os.time` for a
legitimate (non-ambient) purpose today. This test evaluates `platform.now()` from
inside a real sandboxed script (proving `Sandbox.new/1`'s composition wiring — §4.2 of
the design — actually installs it, not just that `Platform.now/0` works when called
directly in Elixir) and asserts the returned string round-trips through
`DateTime.from_iso8601/1` into a UTC `DateTime.t()` (`utc_offset == 0`,
`time_zone == "Etc/UTC"`). A second test calls `Platform.now/0` directly, covering the
Elixir-side API independent of the Lua wiring.

### 5. The time source is injectable — one exact, pre-set timestamp (AC5)

**Why this test exists:** AC5 explicitly distinguishes "exact, pre-set" from "merely
well-formed" — a test that only checked parseability (§4 above) would pass even if
`platform.now()` silently called `DateTime.utc_now/0` at the call site with no
injection seam at all, which is exactly the anti-pattern this requirement's design (§3.2)
exists to avoid ("do not read the system clock directly at the call site"). This test
installs `FixedTimeSource` (a local `@behaviour Letflow.Engine.Lua.Platform.TimeSource`
test double returning a hardcoded `~U[2026-01-01 00:00:00.000000Z]`) via
`Application.put_env(:letflow, :lua_platform_time_source, FixedTimeSource)` in `setup`,
reverted in `on_exit` to whatever value application env held before (config.exs's
`SystemClock` default in normal test runs), and asserts:

- `Platform.now/0` returns exactly `DateTime.to_iso8601(~U[2026-01-01
  00:00:00.000000Z])` — not merely a parseable string.
- `platform.now()` called from inside a script returns the identical exact string,
  proving the Lua-visible wrapper and the direct Elixir call resolve the same injected
  source rather than diverging.
- A follow-up case swaps the source back to `Platform.SystemClock` mid-test and asserts
  the returned value changes (not equal to the fixed one), demonstrating the injection
  is a live, per-call resolution (`Application.get_env/3` read fresh every call, never
  cached) rather than a value latched once at compile or supervision-start time.

This is the one place in this suite that constructs a `DateTime.t()` literal rather
than reading wall-clock time; every assertion in this describe block is deterministic
and does not depend on when the test suite happens to run.

### 6. `sandbox.ex` moduledoc content (AC6)

**Why this test exists:** AC6 requires the moduledoc state findings that only exist as
prose — the 6-of-11/5-undenied count, the specific five function names left undenied by
the library's defaults, the "BEYOND LUA-14's literal wording" framing, the 28→33 count
change, and the `os.setlocale` gap-closure disclosure. None of these are otherwise
verifiable by any other test in this file (a passing per-function denial test proves
the function *is* denied, not that the moduledoc *explains why* it needed denying, or
that a future reader is warned `os.setlocale` was not always covered). `Code.
fetch_docs/1` reads the compiled moduledoc directly, so a future edit that silently
drops this content (rather than a typo that merely rewords it) fails this test.

### 7. `platform.ex` moduledoc content (AC7)

**Why this test exists:** AC7 requires a *binding statement* for a future requirement
(REQ-157) that does not yet exist — there is no code-level mechanism to enforce "don't
add a capability gate to `platform.now` by symmetry" (design §5 explicitly says this
property is enforced by there being no such mechanism, not by a runtime assertion). The
moduledoc is the only artifact carrying that instruction forward to whoever implements
REQ-157, so a test asserting its presence is the only thing standing between this
requirement's design decision and it being silently reversed later. Checks: the
"ungated by design" / "not an omission" framing, the "no capability check, gate, or
permission lookup" statement, the explicit `REQ-157`/`"symmetry"` binding statement, the
injection-mechanism explanation (behaviour + application-env, AC5's testability made
legible from prose), and the `install/1` composition-point statement (`Sandbox.new`
calls it).

### 8. `mix test` and `mix compile --warnings-as-errors` (AC8)

Not asserted by a test in this file — this is TEST-RUNNER's Step 4 responsibility (real
output quoted there), consistent with how REQ-151's own spec treats this criterion.

## No wall-clock or unseeded-randomness dependence

Every test in `platform_test.exs` that needs a specific timestamp uses a hardcoded
`DateTime.t()` literal (`~U[2026-01-01 00:00:00.000000Z]`) via `FixedTimeSource`, never
`DateTime.utc_now/0` in an assertion. The two tests that do call `Platform.now/0` /
`platform.now()` without swapping the source (§4 above) assert only shape/parseability
(`DateTime.from_iso8601/1` succeeds, UTC offset), never a specific value — so they
cannot fail due to *when* the suite runs. No test uses `:rand`, `System.unique_integer/
1` without a fixed seed, or any other unseeded source.
