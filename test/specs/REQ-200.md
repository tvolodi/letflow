# Test Spec: REQ-200 — Instance timeline rendering (actor display names and descriptions)

**Requirement:** REQ-200 (`docs/requirements.yaml`, stage S6) — closes the gap between
REQ-080's already-shipped `GET /api/v1/instances/:id/timeline` and the already-shipped
SPA consumer, per `lib/letflow/design/req200-instance-timeline-rendering.md`. Adds
`resolve_actor_display_name/3` (4-level fallback), `render_description/3`
(event-type-specific + generic fallback), `fetch_display_names_by_actor_id/2` (batched,
N+1-avoiding lookup), and renames `sequence_number`/`created_at` to
`sequence_num`/`timestamp` on the timeline item shape.

**Test tier:** integration, `Letflow.DataCase`/`async: false` — same tier and dispatch
mechanism as the rest of `test/letflow/routers/instances_test.exs` (real Postgres, real
tenant schemas via `TenantFixture.provisioned_tenant!/1`, `Letflow.Routers.Instances.

## Gap-fill performed this pass (TEST-DESIGNER, WF-02 Step 3)

ELIXIR-DEV's initial pass already covered AC1, AC4, AC5, AC6, AC7 completely and
correctly (see rationale per-AC below). The one genuine structural gap was **AC2**:
the requirement text reads "the actor fallback chain is exercised at all four levels
by **four explicit tests**" — the initial pass proved the chain via one combined test
(`"AC2/AC3: all four actor fallback levels resolve, including a deleted user row"`)
that seeded all 4 levels' events plus the AC3 deleted-user case in a single test body,
keyed by `task_id`. That proves the chain works end-to-end but does not satisfy the
AC's explicit "four explicit tests" structural requirement — a single combined test
cannot fail in a way that pinpoints which specific level regressed, and folding AC3 in
as a fifth case obscures that AC3 is a separately-worded acceptance criterion.

**Fix:** split into 5 independent tests, each isolating exactly one fallback input
combination:

- `"AC2 level 1: an event with a resolvable actor_id resolves to that user's display_name"`
- `"AC2 level 2: no actor id, metadata token_description resolves to that"`
- `"AC2 level 3: no actor id and no token_description, metadata actor_label resolves to that"`
- `"AC2 level 4: none of actor id, token_description, or actor_label -- falls to the literal \"system\""`
- `"AC3: an event whose actor_id refers to a user row that no longer exists still falls through, never nil/error"`

Each level test sets up *only* the inputs relevant to that level (e.g. level 2's event
has `actor_id: nil`, not merely an actor_id that fails to resolve, so a bug that
accidentally short-circuits on any non-nil actor_id can't produce a false pass). No
assertion from the original combined test was dropped — every string-equality check it
made survives, now attributed to its own dedicated test. This is strictly additive
coverage restructuring, not new behavior coverage; nothing under test changed.

Additionally strengthened (not required by any single AC, but directly serves AC7's
intent): the AC7 query-count assertion was tightened from `<= 1` to `== 1` on the
shared-actor page, so the test also fails if the batched lookup is ever silently
skipped (a resolver bug that always falls through to a lower fallback level would
otherwise still report a vacuous "0 <= 1" pass). See inline comment at the assertion.

## Why each existing test case is already correct coverage (not restated ACs)

- **AC1** (`"AC1: every item over a 4+ event-type timeline has a non-blank
  actor_display_name and description"`): seeds `INSTANCE_STARTED` (via
  `start_instance!`), `INSTANCE_CANCELLED` (via `cancel_instance!`),
  `INSTANCE_PINS_REBOUND`, and `TIMER_FIRED` — four genuinely distinct
  `event_type`s, confirmed via `assert length(event_types) >= 4` computed from
  `Enum.uniq/1` over the actual response, not assumed from the seed count. Asserts
  non-blank `actor_display_name`/`description` inside a `for item <- items do` loop
  over *every* returned item, not a sample — a description clause that silently
  returns `nil`/`""` for one specific event type (e.g. a copy-paste bug in one `case`
  clause) would be caught here even if a spot-check of the first item would have
  missed it.
- **AC2/AC3** — see gap-fill above.
- **AC4** (`"AC4: INSTANCE_STARTED and a task-completion item render different,
  actor-naming sentences"`): asserts the literal exact strings — `"Instance started by
  Grace Hopper"` and `"Task approve completed by Grace Hopper"` — not just
  inequality or non-blankness. This matters because two different-but-equally-lazy
  implementations (e.g. both event types rendering `"{event_type} by {actor}"`) would
  pass an inequality-only check but fail this exact-string check, which is what AC4's
  "asserted on the actual strings" wording specifically calls for.
- **AC5** (`"AC5: an event type with no specific rendering gets a non-empty generic
  description"`): asserts the exact generic-fallback string
  `"Event TENANT_CUSTOM_LUA_EVENT by Lua Script"` for an event type
  (`TENANT_CUSTOM_LUA_EVENT`) the renderer has no dedicated clause for — proves the
  fallback clause exists and is reachable, not merely that *some* non-empty string
  came back (which a raised-and-rescued exception returning `""` could also produce
  under a weaker assertion).
- **AC6** (`"AC6: response field names match TimelineEntry -- timestamp and
  sequence_num present"`): checks every one of `TimelineEntry`'s declared members by
  name (`Map.has_key?/2` per key) and explicitly refutes the two old names
  (`created_at`, `sequence_number`) are still present — a rename implemented as an
  "emit both" compromise (contrary to the design's explicit rename-not-duplicate
  decision) would fail this test's `refute` lines even though it would pass a
  presence-only check on the new names.
- **AC7** (`"AC7: a page whose events share one actor issues at most one user-lookup
  query"`, now asserting `== 1`): seeds `INSTANCE_STARTED` + 5 `TASK_COMPLETED` events
  (6 total) all sharing one actor id — a naive per-row lookup implementation would
  issue up to 6 `users` queries here, while the batched implementation issues exactly
  1. Uses the project's established named-telemetry-handler pattern
  (`[:letflow, :repo, :query]`, filtered to `metadata.source == "users"` and to the
  test's own pid) rather than an anonymous function, per this file's own inline
  precedent citation (`router_test.exs`'s ISS-0031/GH#90 pattern).
- **AC8** (REQ-080 regressions): not new coverage — verified this pass by re-reading
  the pre-existing `"AC1 -- five read endpoints"` (`GET /:id/timeline` route/shape),
  `"AC2 -- pagination completeness"` (`timeline: every event exactly once across three
  pages, no dup, no gap"`, including the ascending-order check via
  `all_seqs == Enum.sort(all_seqs)`), `"AC3 -- cross-tenant is the same as
  nonexistent"` (`"timeline: cross-tenant id and nonexistent id both 404"`), and `"AC6
  -- permission required on every read endpoint"` (the `/timeline` path is one of the
  five iterated) describe blocks in this same file — all five of AC8's named
  properties (route path, `:InstancesRead`, ascending order, cursor pagination, 404)
  are already exercised by tests that predate this requirement and were confirmed
  unmodified. No new test was needed or added for AC8.
- **AC9/AC10** (no `web/` file touched; `authorization.ex` not modified): these are
  process/diff-scope claims, not runtime behavior — verified via `git diff --stat`
  against `main` (REVIEWER's own handoff already recorded this: "only
  `lib/letflow/instances.ex`, `lib/letflow/routers/instances.ex`,
  `test/letflow/routers/instances_test.exs`, the design doc, and handoff/registry
  bookkeeping changed"). No ExUnit test is the right tool for a diff-scope claim; one
  is not written here, matching this project's own established treatment of identical
  claims on prior requirements' specs.
- **AC11** (`mix test`/`mix compile --warnings-as-errors` pass with real output
  quoted): a process requirement for Step 4 (TEST-RUNNER) and Step 2d/2c's already-run
  results, not a unit test. TEST-DESIGNER does not run tests (not this role's
  function); TEST-RUNNER re-runs the full suite including this file's new tests next.
