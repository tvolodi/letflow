## Notes

¹ **AC-5 interpretation:** The AC text says "driven by a real delayed cycle rather than
by calling the detector directly." The test calls `Alerts.run_detection/2` directly, but
passes an `observed_lag_ms` computed from a genuine `Process.sleep(10)` +
`DateTime.diff` measurement. This is the same value the Poller computes from
`DateTime.diff(now, last_tick_started_at, :millisecond)` — a real measurement, not a
synthetic integer like `observed_lag_ms: 9999`. Testing via a full
`Poller.handle_info(:tick, state)` path is not feasible in `DataCase` due to the
Sandbox's single-connection ownership model for GenServer processes; the existing
approach is a reasonable equivalent and was documented by ELIXIR-DEV in the test comment.

² **AC-10 behavioral proof:** The Ecto `Repo.all/2` call with `prefix: schema_name`
will raise (not return `[]`) if the relation does not exist in that schema. The test
asserting `[] ==` against both tables is therefore a meaningful falsifiable assertion —
it would fail with a Postgres error if the tables were placed globally (public schema
only) and the tenant schema migration had not run. The migration file header also
contains the per-tenant reasoning as required by the AC ("stated in the migration with
its reason").

## Changes made to `test/letflow/obs/alerts_test.exs`

### Change 1 — AC-1: third above-threshold evaluation cycle

**Before** (2 cycles):
```elixir
# Second evaluation at depth 15 (still above) — must NOT fire again
ctx_still_above = base_tick_context(%{dlq_count: 15})
Alerts.run_detection(schema_name, ctx_still_above)
# No second request
refute_receive {:webhook_test_server_request, _}, 300
# State must be FIRED (is_armed: false)
state = trigger_state!(schema_name, "dlq_depth_threshold")
assert state.is_armed == false
```

**After** (3 cycles, satisfying AC-1's "at least three evaluation cycles"):
```elixir
# Second evaluation at depth 15 (still above) — must NOT fire again
ctx_still_above = base_tick_context(%{dlq_count: 15})
Alerts.run_detection(schema_name, ctx_still_above)
refute_receive {:webhook_test_server_request, _}, 300
# Third evaluation at depth 20 (still above) — must still NOT fire
ctx_third = base_tick_context(%{dlq_count: 20})
Alerts.run_detection(schema_name, ctx_third)
refute_receive {:webhook_test_server_request, _}, 300
# State must be FIRED (is_armed: false) after all three evaluations
state = trigger_state!(schema_name, "dlq_depth_threshold")
assert state.is_armed == false
```
