## Gap found and filled

**Gap:** `manifest.json`'s `corpus_schema_version` field (design doc §4.2:
required, `MAJOR.MINOR.PATCH` semver string, and — "No other top-level fields")
was never read by any existing test. The drift-guard's manifest describe block
only ever checks `@manifest["capabilities"]`; a manifest missing
`corpus_schema_version` entirely, or carrying a malformed value (`"v1"`,
`1.0`, `null`, an extra stray top-level key), would pass every test that
existed before this pass.

**Fix:** added a new describe block, `"manifest.json marker schema"`, to
`test/letflow/engine/expr_corpus_drift_guard_test.exs`, with two tests:

1. `"has exactly the two documented top-level keys, no stray fields"` — asserts
   `Map.keys(@manifest)` is exactly `["corpus_schema_version", "capabilities"]`,
   per design §4.2's "No other top-level fields."
2. `"corpus_schema_version is present and is a MAJOR.MINOR.PATCH semver string"`
   — asserts it is a binary matching `~r/^\d+\.\d+\.\d+$/`, per design §4.2/§4.3.

Both tests are real: they fail if `priv/expr_conformance/manifest.json` is
edited to drop, rename, or malform the marker field, and both currently pass
against the committed `manifest.json` (`"corpus_schema_version": "1.0.0"`).

File: `test/letflow/engine/expr_corpus_drift_guard_test.exs` (edit; describe
block appended after "corpus manifest capabilities are drift-guarded too").
