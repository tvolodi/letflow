## Acceptance criteria and test mapping

### AC1 — Usage figure correct immediately after upload

> "a context-module function returns a tenant's current total attached-attachment byte
> usage, correct immediately after an upload/2 call and after a delete/2 call, in that
> order, within one test"

**Test:** `REQ-390: per-tenant storage quota and usage tracking > get_storage_usage/1 returns correct byte count after upload and after delete (AC1, AC4)`

Why it would fail if violated: if `get_storage_usage/1` never increments (or increments
incorrectly), the `assert usage_after_upload == byte_size(raw_bytes)` assertion fails.
Covers both AC1 (upload increments) and AC4 (delete returns to zero) in a single ordered
sequence, as the AC text requires.

---

### AC2 — Over-quota upload refused, no DB rows created

> "a configured per-tenant storage allowance exists and is named/documented; upload/2
> refuses an upload that would exceed it with a distinct error tag, checked before any
> DB write -- a test asserts no repository_artifacts or instance_attachments row is
> created for a refused-for-quota upload"

**Test:** `REQ-390: per-tenant storage quota and usage tracking > upload/2 refuses an upload that would exceed storage quota -- no DB rows created (AC2)`

Why it would fail if violated: if `check_storage_quota/3` is missing or its short-circuit
is removed, `upload/2` would return `{:ok, attachment}` instead of
`{:error, :storage_quota_exceeded}`. The DB-row count assertions also catch a partial
write (artifact inserted, attachment not, or vice versa).

---

### AC3 — Quota check and per-file check independently triggerable

> "the quota check and the existing @max_upload_bytes per-file check are independently
> testable and independently triggerable (a test exercises each without the other firing)"

**Test A:** `REQ-390: per-tenant storage quota and usage tracking > storage_quota_exceeded triggers without hitting file_too_large (AC3)`

- 100 bytes, allowance 1 byte → `{:error, :storage_quota_exceeded}`
- file_too_large cannot fire (100 ≤ 26_214_400)

**Test B:** `REQ-390: per-tenant storage quota and usage tracking > file_too_large triggers without triggering storage_quota (AC3)`

- 26_214_401 bytes, default allowance 1 GiB → `{:error, :file_too_large}`
- quota check is never reached (file_too_large is checked first in `upload/2`)

Why they would fail if violated: swapping the two error tags, or checking quota before
file size, or removing either check, causes at least one of these assertions to fail.

---

### AC4 — delete/2 reflected in usage on next read (covered by AC1 test)

> "removing an attachment (delete/2) is reflected in the usage figure on the very next
> read -- a test asserts the before/after values across upload then delete"

Covered by the same test as AC1 (the AC text requires both in one test sequence).
