# Test Spec: REQ-396 — HUMAN_TASK escalation timer

## Requirement

Add `HUMAN_TASK.escalation_timer_duration` + `escalation_role` to the graph schema, validate
with CHK-21, and wire SCH-04's escalation half (timer fire → original task non-actionable,
new task assigned to escalation role).

**Function:** `Letflow.Definitions.Graph.validate_node_attributes/1`  
**Check:** CHK-21 (`check_human_task_escalation/1`)  
**File:** `test/letflow/definitions/graph_test.exs`

| # | Test name | Fixture | Why it exists |
|---|-----------|---------|---------------|

## AC3 — ExUnit proves timer fire → (a) non-actionable original task, (b) one new task, (c) audit ordering

**Function:** `Letflow.Engine.advance_after_escalation_timer_fired/3` (via `Letflow.Scheduler.fire_timer/2`)  
**File:** `test/letflow/engine/human_task_escalation_test.exs`

**Fixture graph:**
```
START → orig-task (HUMAN_TASK, role: "approver", escalation_timer_duration: "P0D",
                   escalation_role: "role-escalation")
        ─(no condition)→ escalated-task (HUMAN_TASK, role: "role-escalation")
escalated-task ─(no condition)→ end
```

`P0D` is used so the escalation timer is due immediately (same pattern the TIMER
wiring tests use for all their "fires via poll_and_fire" cases).

**Assertion map:**

| Sub-AC | Assertion | Rationale |
|--------|-----------|-----------|
| (a) | `orig_task.status == :cancelled` | The `:cancel_original_task` Multi step sets status to CANCELLED before task activation. |
| (b) | Exactly one task with `node_id == "escalated-task"` and `assignee_ref == "role-escalation"` | `dispatch_escalation_timer_fired/4` follows the fallback edge; `TaskActivation` creates the new task at the landing node's `role`. |
| (c) | `DateTime.compare(orig_task.cancelled_at, new_task.inserted_at) != :gt` | `cancelled_at` is set to `now` at the top of `persist_escalation_timer_fired_advance/7`; the new task's `inserted_at` is set at INSERT time, which is the same or slightly later timestamp in the same transaction. |

**Pre-fix failure (non-existence case):** The code under test (`advance_after_escalation_timer_fired/3`)
did not exist before REQ-396. Therefore the pre-fix failure is "the code under test does not
exist." Per `docs/agents/workflows/WF-02_requirement_implementation.md`'s "When the pre-fix failure
is 'the code under test does not exist'" procedure, at least one mutant was applied and measured:

**Mutant M1:** Remove the `:cancel_original_task` Multi step from `persist_escalation_timer_fired_advance/7`
in `engine.ex`.  
**Measured failure:** Sub-AC (a) — `assert orig_task.status == :cancelled` FAILS (task stays `:pending`).  
1 test failed out of 1 test in the new file; mutant reverted after measurement.

## AC4 — process_route_approval ops-review escalation path reaches ceo-approval

**Function:** End-to-end via `Engine.create/2` + `Scheduler.fire_timer/2`  
**File:** `test/letflow/simulation/req206_swiftroute_test.exs`

Uses an inline graph (module attribute `@ops_escalation_graph`) matching the escalation
structure of `process_route_approval.yaml` but with `P0D` duration (immediate fire) and
no SERVICE_TASKs (to avoid the existing SERVICE_TASK-not-yet-implemented limitation documented
in the file's own moduledoc).

**Steps and assertions:**
1. Seed `@ops_escalation_graph` as an activated definition.
2. `Engine.create/2` → instance is `:active`, token at `ops-review`.
3. Find the escalation timer (exactly one, `timer_type: "escalation"`, `node_id: "ops-review"`).
4. `Scheduler.fire_timer/2` → `{:ok, :fired}`.
5. `ops-review` task: `status == :cancelled`.
6. `ceo-approval` task: exactly one new PENDING task, `assignee_ref == "role-ceo"`.
