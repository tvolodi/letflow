# Test Spec: REQ-429 — MOB-7 mobile internationalisation matching the platform locale policy (REQ-285)

**Requirement:** REQ-429 (`docs/requirements.yaml`, stage S9, owner `MOBILE-DEV`) —
build `apps/mobile/lib/i18n/`: a formatting-locale resolver (tier a) mirroring the
SPA's `resolveSessionLocale`/`PLATFORM_SUPPORTED_LOCALES`/`FALLBACK_LOCALE`
(`web/src/i18n/sessionLocale.ts`), a UI-string-locale resolver (tier b) mirroring
`resolveUiLocale`/`ENTITIES_UI_LOCALES`/`ENTITIES_UI_FALLBACK_LOCALE`
(`web/src/i18n/entitiesMessages.ts`), a tenant-content `{locale: value}` resolver
(tier c) mirroring `resolveLocalizedText`/`resolveExamFieldText`, intl-based
date/number formatting on the tier-(a) locale, and a static guard against hardcoded
`Text(...)` literals.

**Note on this step's division of labor (per WF-02 Step 3's special instruction for
this requirement):** the Dart test code under `apps/mobile/test/` was written by
`MOBILE-DEV` in the mobile implementation step (2b-mobile) and already reviewed and
PASSed by `REVIEWER` for genuine, non-vacuous, per-sub-clause coverage (commit
`638c1855`). TEST-DESIGNER's role here is independent verification — reading the
actual test files and the actual production/SPA source files itself, not taking
REVIEWER's PASS on faith — plus producing this audit-trail spec, plus closing any
gap found. This spec documents that verification; it is not a rewrite of the Dart
test code.

**Requirement's acceptance criteria (verbatim, decomposed into sub-clauses per the
ISS-0880 lesson — a combined assertion silently under-covers a multi-clause AC):**

1. "a Dart test asserts the mobile formatting-locale list equals the SPA's
   `PLATFORM_SUPPORTED_LOCALES` by reading `web/src/i18n/sessionLocale.ts`, and the
   mobile UI-string locale list equals `ENTITIES_UI_LOCALES` by reading
   `web/src/i18n/entitiesMessages.ts` (parse the array literals) rather than
   hand-copied lists, and asserts both fallbacks are `'en'`; the ARB files present
   under `apps/mobile/` are exactly one per `ENTITIES_UI_LOCALES` entry"
   - **1a:** mobile formatting-locale list == `PLATFORM_SUPPORTED_LOCALES`, parsed
     from the `.ts` source at test time (not hand-copied)
   - **1b:** mobile UI-string locale list == `ENTITIES_UI_LOCALES`, parsed from the
     `.ts` source at test time
   - **1c:** both fallbacks == `'en'`
   - **1d:** ARB file count == `ENTITIES_UI_LOCALES.length` exactly, one per entry
2. "a table-driven test asserts the Dart formatting-locale resolver returns the same
   locale as the SPA's `resolveSessionLocale` for at least six input cases, including
   an unsupported tenant default, an unsupported device list, and `'pt-BR'` exact
   match ... and a second table asserts the Dart UI-locale resolver matches
   `resolveUiLocale`'s base-tag rule (e.g. `['ru-RU'] -> 'ru'`, `['de-DE'] -> 'en'`)"
   - **2a:** >=6 table cases for the formatting-locale resolver vs. `resolveSessionLocale`,
     including unsupported tenant default / unsupported device list / `pt-BR` exact match
   - **2b:** table for the UI-locale resolver vs. `resolveUiLocale`'s base-tag rule,
     including the two named examples
3. "a test asserts a tenant `{locale: value}` map resolves UI locale -> `'en'` ->
   first non-empty value -> `''` ..., covering each step of that chain and a
   plain-string value passing through unchanged"
   - **3a:** UI-locale-key hit
   - **3b:** `en`-fallback
   - **3c:** first-non-empty fallback
   - **3d:** all-blank -> `''`
   - **3e:** plain-string passthrough
4. "a test renders a date and a number under `'de-DE'` and `'en-US'` and asserts the
   locale-specific formatting differs as intl defines"
   - **4a:** date formatting differs `de-DE` vs. `en-US`
   - **4b:** number formatting differs `de-DE` vs. `en-US`
5. "a guard test fails on a string literal passed directly to a `Text` widget under
   `apps/mobile/lib` (outside an allowlist of non-user-visible cases such as keys),
   with a self-test, and passes on the real tree"
   - **5a:** guard self-test proves non-vacuous (fires on an injected literal fixture)
   - **5b:** guard passes against the real `lib/` tree
6. "`docs/mobile/requirements.md`'s MOB-7 note references REQ-285,
   `web/src/i18n/sessionLocale.ts` and `web/src/i18n/entitiesMessages.ts` and states
   the two-tier split, and the 2026-08-22 text is still present"
   - **6a-6e:** reference REQ-285 / sessionLocale.ts / entitiesMessages.ts / two-tier
     split stated / 2026-08-22 text preserved — doc-content, not a Dart test
7. "`cd apps/mobile && flutter analyze && flutter test` pass, real output quoted"
   - command-execution criterion, not a Dart test

**Test tier:** Dart unit tests (`flutter_test`), pure-function and static-source-scan
style; no widget pumping except AC5's guard, which operates on raw file text, not a
rendered widget tree. All tests are synchronous/deterministic — no wall-clock
dependency, no unseeded randomness.

## Independent verification performed (not a restatement of REVIEWER's claims)

For each sub-clause, I read both the Dart test file and the production file(s) /
SPA source file(s) it claims to check, myself, in this session.

### AC1 — `apps/mobile/test/i18n/formatting_locale_test.dart` + `ui_locale_test.dart`

- **1a** — `formatting_locale_test.dart`'s `_parsePlatformSupportedLocalesFromSpaSource`
  regex-extracts `PLATFORM_SUPPORTED_LOCALES` directly from
  `web/src/i18n/sessionLocale.ts` (confirmed: that file's line 32 declares
  `export const PLATFORM_SUPPORTED_LOCALES = [...]` with the exact 10-entry list
  `apps/mobile/lib/i18n/formatting_locale.dart`'s `kPlatformSupportedLocales`
  constant also lists) and asserts equality — test `AC1a`. Not a hand-copied
  list: the test reads the `.ts` file at run time, so drift would fail this test.
- **1b** — `ui_locale_test.dart`'s `_parseEntitiesUiLocalesFromSpaSource` does the
  same against `web/src/i18n/entitiesMessages.ts` (confirmed line 34:
  `export const ENTITIES_UI_LOCALES = ['en', 'ru', 'kk'] as const`) — test `AC1b`.
- **1c** — `formatting_locale_test.dart`'s `'AC1c (formatting half)'` test asserts
  `kFormattingFallbackLocale == 'en'`; `ui_locale_test.dart`'s `'AC1c (UI half)'`
  test asserts `kEntitiesUiFallbackLocale == 'en'`. Confirmed against SPA source:
  `sessionLocale.ts` line 50 `export const FALLBACK_LOCALE: ... = 'en'`;
  `entitiesMessages.ts` line 37 `export const ENTITIES_UI_FALLBACK_LOCALE: ... = 'en'`.
- **1d** — `ui_locale_test.dart`'s `'AC1d'` test lists `lib/i18n/l10n/*.arb`, reads
  each file's `@@locale`, and asserts the resulting set equals
  `kEntitiesUiLocales` **and** the count equals `kEntitiesUiLocales.length` (so
  duplicates/extras are caught, not just set-equality). Confirmed directly:
  `apps/mobile/lib/i18n/l10n/` contains exactly `app_en.arb`, `app_kk.arb`,
  `app_ru.arb` — three files for the three-entry `['en', 'ru', 'kk']` set.

### AC2 — same two files

  (supported device locale wins), TC-2 (unsupported device list -> fallback), TC-3

- **2b** — `ui_locale_test.dart`'s `AC2b` group has 7 cases including both named

### AC3 — `apps/mobile/test/i18n/localized_text_test.dart`

Each sub-clause has its own distinct test (the file's own header comment cites the
ISS-0880 lesson explicitly):
- **3a** `AC3a` — `{'en':'Hello','ru':'Привет','kk':'Сәлем'}` at UI locale `'ru'` ->
  `'Привет'` (the UI-locale key, not `en`).
- **3b** `AC3b` — UI-locale key absent, `en` present -> the `en` value.
- **3c** `AC3c` — neither UI-locale nor `en` present -> first non-empty value in
  map order (`{'kk':'Сәлем','fr':'Bonjour'}` -> `'Сәлем'`).
- **3d** `AC3d` — empty map and an all-blank-valued map both -> `''`.
- **3e** `AC3e` — a plain `String` value passes through unchanged.
Confirmed against `localized_text.dart`'s `resolveLocalizedText`: the map branch's
precedence order (`value[uiLocale]` -> `value['en']` -> first non-empty -> `''`)
and the `is String` passthrough branch match the test expectations exactly, and
in turn mirror the SPA's `resolveLocalizedText`/`resolveExamFieldText` chain the
requirement's own description cites.

### AC4 — `apps/mobile/test/i18n/catalogue_formatting_test.dart`

- **4a** — `AC4a` formats `DateTime(2026, 3, 4)` via `localizedDateFormat('MMMM d,
  y', ...)` under both locales and asserts the outputs differ and contain the
  locale-correct month name (`'März'` vs. `'March'`).
- **4b** — `AC4b` formats `1234.5` via `localizedDecimalFormat(...)` under both

  (`'1.234,5'` vs. `'1,234.5'`), which is `intl`'s own documented behavior for
  these two locales, not an arbitrary expectation.

### AC5 — `apps/mobile/test/guards/text_literal_guard_test.dart`

  `checkRealLibTree(Directory('lib'))` against the actual `apps/mobile/lib` tree
