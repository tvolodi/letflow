# REQ-432 — Publish/retire service versions and rebind pins from the GUI

## Requirement text (`docs/requirements.yaml`, REQ-432)

Frontend-only follow-on to REQ-373 (service-catalog version lifecycle) and
REQ-399 (case-detail pin provenance panel). Builds: (1) `publishVersion` /
`retire` client functions and PLATFORM_ADMIN-gated controls on
`ServicesPage.tsx`; (2) a `rebindPins` client + rebind dialog (required reason)
on `InstancePinsPanel.tsx`; (3) `INSTANCE_PINS_REBOUND` history rendering with
actor, prior version, new version and reason (EO-005); (4) the named pipeline
spec. Out of scope: any change to `Letflow.ServiceCatalog`, `PinResolver`,
`PinRebind`, or REQ-373/REQ-399 routes.

Design: `lib/letflow/design/req432-rebind-pins-publish-retire-ui.md`.

## Scope note

Real executable surface exists (`web/` TypeScript). FRONTEND-DEV (Step 2b) wrote

against the nine acceptance criteria by reading the assertions, fixed the four

## Honesty statement (read first)

* **Proven by runnable unit/component tests (vitest, green):** AC2, AC3, AC4,
  AC5, AC9, and the UI half of AC6 and AC7.
* **Proven only by the Playwright pipeline spec, which has NOT run green:**
  AC1 entirely; the live-backend halves of AC6 (two distinct versions rendered
  from real pins data) and AC7 (in-flight step). Cause: Keycloak on
  `localhost:8094` is shadowed by `wslrelay.exe` on this host
  (`assertServiceReadiness` -> ECONNRESET), so the spec has only been compiled
  and listed (`npx playwright test --list`: 1 test). Its step 02/07 selector
  assumptions are unproven live (stated in the spec header).
* **Unverifiable on success, regardless of host:** the "in-flight step completes
  without error" half of AC7. Backend gap M5:
  `ServiceTaskDispatcher.catalog_lookup_stub/2` returns
  `{:error, :not_registered}` unconditionally, so a catalog SERVICE_TASK always
  ends `EXECUTION_ERROR/request_build_error` (design sections 7.3 and 9). Pipeline
  step 03 asserts the two designed outcomes (success, or that exact error) and
  logs which occurred; it cannot demonstrate success until the backend is fixed.
* **Proven by command, not by a test:** AC8 (git-diff fence).
