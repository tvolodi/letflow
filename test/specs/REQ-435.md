## Recorded gaps (not silent)

- `mix ecto.rollback` / `mix ecto.migrate` real output (criterion 1) is not an ExUnit test; see above.
- `System.halt(1)` branches of the mix task (failed tenant, missing pepper) cannot run inside the test VM; the failure behaviour is tested at `Backfill.run/1` and the halt lines by source inspection (TASK last test).
- Pepper boot checks: now covered by BOOT (see the D-C table). The `<<0xFF::256>>` literal in `config/runtime.exs` is a 256-bit INTEGER 255, not 32 bytes of 0xFF, so an all-`ff` pepper boots: BOOT "all-0xFF" FAILS against current code (implementation bug reported to ORCH, not worked around).
- Same-identity JIT username race (the `{:existing, _}` branch via the username index) is reachable only by a genuine race; CONC exercises it statistically (4 rounds), the deterministic different-identity branch is in ID.
- Callers: six existing test files pass `login_directory: :skip` although their fixtures DO have a `tenants` row (design 15.1 allows `:skip` only "where the fixture prefix has no tenants row"); flagged to ORCH as a minor deviation.
- D-C lock-on-current-key: asserted via `pg_locks` on the test's own connection, not as contention from a second connection (the sandbox cannot show cross-connection blocking; CONC already proves real contention for the pre-existing single-key lock).

## 0043 D-C delta (key_id, PEPPER_ID, previous pair, dual-read)

Design section 15.1 "Additional tests required by 0043 D-C" (items 1-8). Peppers in tests are
`Fx.pepper/1` (derived, never real) swapped via `Fx.swap_keys!/2`, which sets
`:login_directory_keys` and restores it in `on_exit/1`.
