## Notes and deliberate choices

- **"Exactly one notifier submission" is a call trace.** `Dispatch.submit/3` is counted with `:erlang.trace` + `trace_delivered/1` from a separate collector process (a process that is its own tracer emits no trace messages). The router runs in the test process, so the count is exact.
- **"One query" is counted for the calling process only** (`[:letflow,:repo,:query]` filtered on `self()`). The notifier task issues no query by construction, enforced by the source guard (no `Repo` anywhere under `lib/letflow/login_discovery/`).
- **Lookup failure is induced with `SET LOCAL search_path TO pg_catalog`** in the test's sandbox transaction: the one query fails with `undefined_table`, no lock is taken, and the rollback restores everything.
- **Not covered / recorded gaps:** (1) the INV-4 log capture is a dedicated test plus per-risky-path assertions, not a literal handler spanning the whole suite; (2) the real-host UAT scenario of the client-IP criterion (needs the REQ-439 nginx realip action on QA) is UAT-RUNNER's, not an ExUnit test; (3) a crash of the OUTER dispatch closure cannot be forced from outside (every body is wrapped); C-4 is covered by the closure grep guard; (4) the `:prod` boot refusal with the mount enabled belongs to REQ-439 (not retested); (5) the wall-clock TM test cannot prove constant time at sub-millisecond granularity on Windows.
