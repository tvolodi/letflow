# REQ-439 -- Trusted-proxy client IP (REQ-CIP): test spec

Design authority: `lib/letflow/design/req439-trusted-proxy-client-ip.md` (s7 AC map, s3 pinned
OTP parse facts). Implementation: `lib/letflow/plugs/client_ip.ex`, `config/runtime.exs`,
`config/config.exs`, `config/test.exs`.

Test files:

| File | Style |
|---|---|
| `test/letflow/plugs/client_ip_test.exs` | pure table tests + `Plug.Test` conns + stub `Plug.Router` pipeline; no DB use, deterministic (no clock, no randomness) |
| `test/letflow/client_ip_runtime_config_test.exs` | `mix run --no-start` subprocess per case (`@moduletag :slow`; MIX_ENV=prod cases also `:prod_build`), modelled on `secrets_runtime_config_test.exs` |

AC9 (nginx/.env.example text) and AC10 (empty `git diff` on four named files, security

## AC1 -- empty list / untrusted peer: client_ip == remote_ip

- `resolve/3` "ignores the header entirely when the peer is not trusted": empty list, peer
  outside the list, v6 peer vs v4-only list, and a mapped untrusted peer returns the original
  (un-normalised) peer term. Why: the whole point is that a caller-chosen value can never win
  without a trusted TCP peer (INV-5).
- `call/2` "empty trust list ..." and "peer outside the list ...": same through the plug, with
  X-Forwarded-For present.

## AC2 -- trusted peer, valid single X-Real-IP honoured; everything else falls back

- `resolve/3` "trusted peer, single header value": IPv4, IPv6, whitespace trimmed, mapped
  `::ffff:1.2.3.4` returned as the unnormalised 8-tuple (pins design s3 rule 4), v6 trusted peer,
  mapped trusted peer, `/0` trust.
- `resolve/3` "falls back to the peer when": zero values, two values (identical and different),
  comma lists, empty/blank, garbage, hostname, `1.2.3.256`, `1.2`, `010.0.0.1`, `0x7f.0.0.1`,
  `[::1]`, `1.2.3.4/8`, `1.2.3.4:80`, `fe80::1%eth0` (the `%` rows), embedded space/newline/NUL/
  NBSP, non-UTF-8 bytes (`<<0xFF>>` alone and inside an address; asserts no exception, i.e.
  totality), and a non-binary list element. Why each: these are the pinned OTP
  `parse_strict_address/1` facts plus the explicit pre-checks; an OTP change or a dropped
  pre-check flips a row.
- `call/2` "two X-Real-IP header lines": built via `conn.req_headers` directly because
  `Plug.Test.put_req_header/3` overwrites; asserts two elements really exist before asserting
  the fallback.

## AC3 -- X-Forwarded-For never changes the result; remote_ip not rewritten

- "cross-product" test: 3 peers x 3 trust lists (empty, `10/8`, `0/0`) x 7 X-Real-IP shapes
  (absent, v4, v6, comma, garbage, empty, two lines) x 6 XFF shapes x Forwarded present/absent
  (= 756 combinations); for each, the result with XFF/Forwarded equals the result without, and
  `conn.remote_ip` equals the original peer after the plug runs.
- XFF-alone-from-trusted-peer and X-Real-IP-wins-over-XFF rows.

## AC4 -- CIDR matching table and parse_cidrs/1

- `trusted?/2` table (about 40 rows): v4 /8 first/last/just-outside, /9 boundary, /0, /32,
  bare address, host bits set in base, v6 /32 and /33 boundaries, /0, /128, bare address,
  cross-family non-matches, IPv4-mapped peer matching v4 CIDRs and not v6 ones, mapped cidr
  /104 stored as v4, mapped cidr /64 staying v6 (never matching), multi-entry lists.
- `parse_cidrs/1` accepts (blank list, trimmed segments, order, mapped normalisation) and
  rejects with the bare `{:error, :invalid_cidr}`: `10.0.0.0/8/8`, `/8`, `10.0.0.0/`,
  `/33`, `::/129`, `fe80::1%eth0`, `/+8`, `/-1`, `/ 8`, `/0008`, a non-ASCII digit, hostnames,
  brackets, port, whole-list failure (no partial result), control bytes, NBSP, and non-UTF-8
  (`<<0xFF>>`, no exception). A term-shape test shows the error carries no value (INV-4).

## AC5 -- runtime config (subprocess)

`MIX_ENV=test` cases: unset gives `[]` (and enabled true); valid list parses to tuples in order;
invalid entry exits nonzero, names `LETFLOW_TRUSTED_PROXIES`, and the sentinel value and valid
neighbouring entry do not appear in output; out-of-range prefix invalid; `true`/`false`
accepted; `yes`/`TRUE`/`1` and a sentinel exit nonzero with the fixed message and no echo.
Defaults: `enabled` false in prod, true in dev/test (the prod default case and the unset test/dev
cases). The in-process `parse_enabled/2` table pins nil/blank/true/false/other.

## AC6 -- prod boot refusal

In-process: `boot_check/3` decision table (disabled always `:ok`; prod+enabled+[] is the error;
dev/test+enabled+[] is `:warn`; non-empty list `:ok`; any `/0` entry, including a normalised
`::ffff:0:0/96`, is `:warn_zero_prefix`, in every env).
Subprocess (MIX_ENV=prod, `:prod_build`): enabled + unset list exits nonzero naming both
variables; enabled + blank list likewise; enabled + non-empty list boots with the parsed list;
disabled + empty list boots; the refusal precedes the `DATABASE_URL` raise and carries no env
value; an invalid list raises in prod without echo. MIX_ENV=dev: empty list boots with the fixed
warning exactly once; disabled / non-empty list: no warning. `/0` boots with the fixed `/0`
warning exactly once.

## AC7 -- plug reads no body

A conn whose adapter is a module raising on `read_req_body/2`; the test first proves the adapter
raises when `Plug.Conn.read_body/1` is called, then runs the plug (trusted and empty list) and
asserts the result.

## AC8 -- stub pipeline

Two test-only `Plug.Router` modules (`ClientIp` with a trusting list / with `[]`, then
`:match`/`:dispatch`, a route responding with `inspect(conn.assigns.client_ip)`): two X-Real-IP
values behind one trusted peer yield two distinct client_ip values; with `[]`, two spoofed values
and no header all give the peer; an untrusted peer behind the trusting router is unaffected.

## Config-read test (design s2 / invariant 6)

`call/2` with no `:trusted_proxies` opt reads application config at call time: the test asserts
the `config/test.exs` default is `[]`, then flips the env and shows the result flip, restoring the
env in `on_exit`. Why: guards the compile-time-bake bug (`init/1` must not read config).

## Fail-first evidence

The code under test existed before these tests, so "fails against pre-fix code" is trivial. The
mandatory mutation evidence (mutants applied only in a throwaway worktree, with measured kill
counts) is in the TEST-DESIGNER handoff.
