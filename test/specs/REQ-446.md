# Test Spec: REQ-446 -- Named, scoped permissions for the formerly `:Unknown` routes

**Requirement:** REQ-446 (`docs/requirements.yaml`, AMENDED 2026-10-06; Q-963 / GH #2234). Design:
`lib/letflow/design/req446-named-scoped-permissions.md` (section 5 lists the tests, section 4 the
SCOPE RULE statement). Acceptance criteria are quoted by number as the design's section 2 maps them.
**Test tier:** unit + integration (real Postgres, real tenant schemas, router-level dispatch; no
mocks). No property test: there is no closed state/transition set.

Only `lib/` change under test: INV-10 response shaping in `lib/letflow/routers/promotions.ex`
(`GET /promotions/platform-events` and `GET /promotions/:id/context`): a caller that is not a
platform-tenant operator never receives a tenant id other than its own (every map key ending in
`tenant_id` whose value is not the caller's own id, compared case-insensitively, is omitted, at any
depth through maps and lists; `/context` does not descend into the top-level `entries`).

Shared helpers (design OQ-4, decided here): `test/support/promotion_scope_fixture.ex`
(`Letflow.Support.PromotionScopeFixture`: `unique_key/1`, `observable/1`, `insert_active_definition!/3`,
`two_version_history!/2`, `seed_review!/4`, `artifact/0`, `register_event_type!/1`,
`append_fixture_event!/2`, `snapshot/1`). The older private copies in `promotion_scope_test.exs` and
`routers/promotions_test.exs` are left as they are. All new modules are `async: false` (VM-global
platform pin and query telemetry); the pin is restored by `Letflow.Support.PlatformTenantFixture`'s
`on_exit`. Nothing depends on wall-clock time; cursor strings are never compared (each embeds a mint
time).

## Test cases

### T-1 AC8 / AC9 -- `test/letflow/routers/req446_cross_tenant_denial_test.exs`

One table-driven test, `every re-keyed route: A's admin with B's identifiers gets the nowhere 404 and
B is untouched`, one entry per route; caller table `@callers` (today `PLATFORM_ADMIN` of non-platform
tenant A, pin on P; REQ-447 adds a `TENANT_ADMIN` as one more line). Why: the rows exist in several
files today; none compares raw bytes for all twelve and snapshots B, and three routes (GET
`/promotions/:id`, run-assertions with B's review id as the path id, rollback with a B-only process
key) had no cross-tenant test at all.

Per identifier row: the foreign and the nowhere request answer 404 with equal `observable/1` (status,
body, headers but `x-request-id`); the body names none of B's tenant id, slug, review id, B-only
process key; no query of the A calls touches B's schema (`touches_tenant?/2`); the snapshot of A, B
and P (definitions with status/version, reviews with status and row version, assertion-run count) is
unchanged. Then the CONTROL (B's own admin, B's own identifier) must answer the stated status, so the
404 is the authorization denial and not a malformed request (apply, run-assertions and rollback
validate the body before the lookup, so the full valid body is sent on both).

| # | Route | Control status (B's admin) |
|---|---|---|
| 1 | `POST /promotions` | 422 `Empty Promotion Plan` (source = target = B) |
| 2 | `POST /promotions/plan` | 422 `Empty Promotion Plan` |
| 3 | `GET /promotions/:id` | 200 `{"assertion_run": null}` |
| 4 | `GET /promotions/:id/context` | 200, `review_id` = `R_B` |
| 5 | `POST /promotions/:id/approve` | 200 `approved` |
| 6 | `POST /promotions/:id/reject` | 200 `rejected` |
| 7 | `POST /promotions/:id/apply` | 409 invalid transition (review is `pending_review`) |
| 8 | `POST /promotions/:review_id/run-assertions` | 200, six keys, `assertions_failed` 0 |
| 9 | `POST /definitions/:process_key/rollback` | 200, `version` 1.0.0, `rolled_back_from_version` 2.0.0 |
| 10 | `POST /tenants/:test_tenant_id/promote/:process_key` | 409 duplicate version |
| 11 | `GET /promotions` | baseline form: A's response before and after B's review is written is byte-identical and names nothing of B; B's admin sees `R_B` (200) |

Row 7/8 note: the A call on `R_B` is refused because `R_B` is absent from A's schema; the STORED-id
re-check (`stored_tenants_authorized?/3`) is exercised by `promotion_scope_test.exs` ("a stored foreign
SOURCE or TARGET ..."), which is the test that catches mutant M10 below, not T-1.

### T-2 AC3 -- `test/letflow/routers/promotion_scope_test.exs`, "every other role is denied 403 on every row"

`CANDIDATE` and `AGENT_RUNNER` added to the role grid (nothing removed): 403 on all twelve rows, for
the A and the P fixture. Why: the pure `evaluate_access/2` grid covered all five roles, but router
level covered only three plus no role.

### T-4 AC5 -- `test/letflow/api/platform_scope_inventory_test.exs`, describe "G2: route table"

The G2 (a) predicate is now one helper (`offending_routes/1`) used by the existing test unchanged in
effect. New: `G2 (a) flags a fixture router that declares :Unknown as an explicit key` (a throwaway
router compiled with `Code.compile_string` declares one named and one explicit-`:Unknown` route; it
compiles, and exactly the `:Unknown` route is flagged; a control shows the named route alone is not),
and `a route declared with NO policy key does not compile`. Why: before, the explicit-literal form was
only caught by a predicate never run against a bad fixture.

## KNOWN residuals (accepted exceptions; NOT tested as failures)

Accepted, TRACKED: Q-981 / GH #2266 / ISS-0999 (the issue file ships with that fix PR, not this one):

* `source_definition_id`, `review_id` and `actor_id` in the platform-events payload/envelope are
  not tenant ids and are kept (design OQ-6; `review_id` and `actor_id` likewise).
* Key-suffix-only matching: a foreign tenant id under a key that does not end in `tenant_id`, or
  embedded in a string value, is not caught (design OQ-8).

Accepted, no issue:

* The serialised plan's `entries` graph JSON (`before`/`after`) is not shaped. T-8
  (`context_nested_tenant_ids_walked_but_entries_not_descended`) pins the current behaviour (left as
  stored) as documentation, not as a requirement.
* The free-text `error` of a `PROMOTION_ASSERTION_TEARDOWN_FAILED` event is not scanned (design OQ-7).
