# Test Spec: REQ-452 — UAT actor roster, `expect_refusal`, rules SCHEMA-7..12

**Requirement:** REQ-452 (`docs/requirements.yaml`, stage S7, owner ELIXIR-DEV).
**Design:** `lib/letflow/design/req452-uat-actor-roster-design.md` (section 6).
**Implementation commit:** `f5c975fc`.

**Test tier:** unit, hermetic, `async: true`, no DB. Each fixture corpus (scenario files plus a
JSON-encoded roster, which YAML parses) is written to a tmp dir and checked via
`Mix.Tasks.Letflow.CheckUatScenarioSchema.check_paths/3`. Only T-LIVE-ROSTER and T-EXEMPT-FROZEN read
the real files.
Test file: `test/mix/tasks/letflow_check_uat_scenario_schema_test.exs` (REQ-452 tests appended after
the REQ-358 tests; 61 tests in the file).

## Acceptance criteria -> tests

1. **AC1** roster exists, task passes on the corpus, counts of login actors / in roster / unresolved.
   - `T-LIVE-ROSTER`: real `actors.yaml` + every real scenario gives zero violations, `missing == 0`,
     `login_actors == in_roster + unresolved`. Exists because a roster that drifts from the corpus
     must fail CI, not just the fixtures.
   - `T-RENDER-COUNTS`, `T-RENDER-NO-STATS`: the "Actor roster:" line carries the counts; reports
     without `actor_stats` still render.
   - `T-R452-BASE`: the shared fixture corpus is clean, so each rule test below isolates one rule.

2. **AC2** one test per rule (a)-(e) with a corpus violating only that rule, asserting tag, file,
   actor or scope.
   - (a) `T-SCHEMA-7` (unknown actor); negatives `T-SCHEMA-7-NEG` (unresolved passes),
     `T-SCHEMA-7-NONLOGIN` (`actor-system-*`, `actor-any` ignored).
   - (b) `T-SCHEMA-8` (role not in list); `T-SCHEMA-8-FOLLOWS-ROLES` (passes when the list gains it);
     `T-KNOWN-ROLE-NAMES` (`known_role_names/0` equals `Authorization.roles/0`).
   - (c) `T-SCHEMA-9` (tenant actor with PLATFORM_ADMIN fires without exemption);
     `T-SCHEMA-9-LEGACY` (legacy_platform_admin exemption works); `T-SCHEMA-9-PLATFORM` (platform
     tenant is fine); `T-SCHEMA-12-LEGACY-STALE` (exemption for a non-admin actor is rejected).
   - (d) `T-SCHEMA-10` (platform actor in a non-platform scope); `T-SCHEMA-10-ALLOWED` (listed id with
     reason passes); `T-SCHEMA-10-EMPTY-REASON` (empty reason is SCHEMA-12; roster fails to load so
     cross rules do not run).
   - (e) `T-SCHEMA-11` (scope without refusal); negatives `T-SCHEMA-11-NEG-FLAT`,
     `T-SCHEMA-11-NEG-BRANCH`, `T-SCHEMA-11-NEG-EXEMPT`, `T-SCHEMA-11-ONE-OF-MANY`,
     `T-SCHEMA-11-COMPANY-ID` (scope resolved from `company_id`).

3. **AC3** no Ported-verbatim scenario modified: not a unit test. ORCH/RELEASE-VALIDATOR quote
   `git diff --stat origin/main -- test/fixtures/uat/scenarios`.

4. **AC4** schema doc: documentation, not a unit test; checked by RELEASE-VALIDATOR reading the doc.

5. **AC5** `refusal_coverage_exempt` subset of the frozen initial list, test fails when a scope is added.
   - `T-EXEMPT-FROZEN`: the real roster's list minus the list frozen in the test
     (`bilimbaga meridian platform swiftroute vortex`) is empty.
   - `T-EXEMPT-FROZEN-BITES`: a fabricated `newscope` makes the same helper report a difference.
   - `T-EXEMPT-SHRINK-OK`: a smaller list passes.

6. **AC6** compile/format/test/check: run, not designed.

## SCHEMA-12 shape tests (design D5; roster and step-key integrity)

`T-SCHEMA-12-NON-BOOLEAN`, `T-SCHEMA-12-NON-BOOLEAN-BRANCH`, `T-SCHEMA-12-BOOLEAN-OK`,
`T-SCHEMA-12-MISSING-ROSTER` (clean violation, `actor_stats == :not_loaded`, no crash),
`T-SCHEMA-12-EMPTY-ACTORS`, `T-SCHEMA-12-BAD-SINCE`, `T-SCHEMA-12-ENTRY-SHAPE`,
`T-SCHEMA-12-UNRESOLVED`, `T-SCHEMA-12-ALLOWED-NOT-STRING`, `T-SCHEMA-12-EXEMPT-SHAPE`. They exist
because a malformed roster would otherwise crash the task or silently weaken rules (a)-(e).
