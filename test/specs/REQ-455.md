# Test Spec: REQ-455 -- Definition validator gaps (reachability, default route, data-before-collected, unbound task roles)

**Requirement:** REQ-455 (`docs/requirements.yaml`, stage S3, owner ELIXIR-DEV).
**Design:** `lib/letflow/design/req455-definition-validator-gaps.md` (section 9 is the AC mapping).
**Implementation commit:** `41b51aaa`.

**Test tier:** unit (pure, `async: true`) for the validators; integration (`Letflow.DataCase`, real
Postgres, `async: false`, one freshly provisioned tenant per test, `System.unique_integer/1` names) for
install, create/update/activate and the HTTP validate route. No wall-clock, no unseeded randomness.

Violation structs carry only `code` and `message` (no node/edge id field), so "asserts the offending
node or edge id" means the id is asserted inside the message.

## Acceptance criteria -> tests

1. **AC1** (design classifies each candidate, with file and line). Design artefact, not an executable
   test; re-verified by CODE-DESIGN-VALIDATOR. Out of this spec's executable scope.

2. **AC2** (per built check: one minimal violating definition asserting code AND node/edge id, plus a
   valid neighbour).
   - CHK-22 `:unreachable_node`: island `x<->y` beside `start->end`; asserts two violations naming `x`
     and `y`. The same graph is asserted clean under `validate_graph/1`, `validate_node_attributes/1`
     and `validate_edge_conditions/1` (`assert_legacy_validators_clean/1`), so the test proves only the
     new check can catch it. Neighbour: island wired in from `start`. Also: dangling edge / missing START
     never raise; duplicate node ids reported once.
   - CHK-23 `:no_path_to_end`: gateway loop `h<->k` with no exit; asserts `h` and `k`; legacy validators
     clean (CHK-06 allows a cycle through a gateway, which is exactly the hole). Neighbour: loop with an
     exit to an END. Also: missing END reports nothing (CHK-02 owns it).
   - CHK-24 `:no_default_route`: gateway with two conditional edges, no default; asserts the gateway id;
     legacy validators clean. Neighbour: same gateway with an `is_default` edge. Also: a gateway with no
     outgoing edge is not reported (isolated_node owns it); a HUMAN_TASK without a default is NOT
     double-reported (`validate_flow/1` empty while CHK-19 still fires).
   - `:variable_never_collected`: HUMAN_TASK edge reading `ghost` with declared `{a}`, a form without
     `ghost`, no writer upstream; asserts edge id `e-cond`, the node, and variable `ghost`. The design is
     deliberately narrow (certain case only), so each neighbour removes exactly one conjunct and must
     pass: variable declared; own form declares it; upstream form declares it; upstream SERVICE_TASK;
     open HUMAN_TASK form; SUB_PROCESS with no interface or an interface outputting it; empty declared
     fields. Boundary tests: a writer on a sibling branch (not an ancestor) and a writer downstream of the
     task both do NOT suppress the violation; a nested path reads its root; a gateway-sourced edge is
     reported only by the older `:undeclared_variable_reference`, not twice; blank condition skipped.

3. **AC3** (ISS-0928 shape rejected, with a test). Both shapes, because the design found the requirement
   text and `docs/issues/ISS-0928.yaml` disagree on the node kind:
   - gateway shape (the real defect): `validate_flow/1` returns `:no_default_route` naming `kyc-routing`
     (unit), and `Definitions.create/2` returns `{:error, {:graph_validation_failed, [...]}}` and writes no
     row (DB).
   - literal service-task shape: `validate_edge_conditions/1` returns `:unexpected_edge_condition` twice
     and `validate_flow/1` returns `:no_default_route` naming the task. Neighbours: unconditional edge, and
     conditional plus default.

4. **AC4** (check 4: role names in warnings, nothing bound). `role_binding_install_test.exs`:
   `SolutionPack.install/3` of a definition whose HUMAN_TASKs route to three unbound roles (two `role`,
   one `escalation_role`) lists each role and node id in `result.warnings`, the install still succeeds, and
   `Repo.aggregate(TenantRole, :count, ...)` is identical before and after and the role names are absent
   from `list_roles`. Neighbours: a bound role is not warned about; an all-bound pack yields no
   `unbound_task_role:` line; a role bound in ANOTHER tenant does not count (tenant isolation).
   Validate: `validate_definition_graph/2` returns `valid: true` with the warning in `:warnings`, `[]` when
   bound; `POST /definitions/:id/validate` 200 body carries `"warnings"` beside empty `"findings"`.

5. **AC5** (every shipped / seeded definition is validated). `shipped_definitions_validation_test.exs`
   discovers definitions by structure (`priv/**/*.json`, `test/fixtures/qa/*.json`,
   `test/fixtures/simulation/**/process_*.yaml`; a `"graph"` with `nodes`/`edges` lists or a pack
   `"definitions"` list) and runs all four graph validators plus `SemanticValidation.validate/2`, asserting
   zero violations with the file path in the failure. Two guards stop the discovery silently shrinking:
   every fixture path referenced by `scripts/seed_*_definition.sh` must have been discovered (and at least 6
   are referenced), and at least 12 definition files (>= 6 QA, >= 6 simulation) are discovered.

6. **AC6** (`mix compile --warnings-as-errors`, `mix format --check-formatted`, `mix test`,
   `mix letflow.check_boundaries`). Run by TEST-RUNNER / CI; `mix letflow.check.test` was run on the new
   files by TEST-DESIGNER (see handoff).

**OQ-1** (already ACTIVE definition is not re-validated at activate and is not deactivated):
`flow_validation_wiring_test.exs` activates a valid definition, rewrites its stored graph to the
default-less gateway via `Repo.update_all`, then calls `activate/2` again and asserts
`already_active: true` with status still `:active`.

## Wiring tests (why they exist)

`validate_flow/1` being correct is not enough; the requirement is that it runs wherever the existing checks
run. `flow_validation_wiring_test.exs` proves `create/2`, `update/3` (stored graph unchanged on refusal),
`activate/2` of a DRAFT inserted past `create/2` (stands for a pre-REQ-455 draft; refused with
`{:semantic_validation_failed, ...}`, status stays `:draft`) and `validate_definition_graph/2` all use it.

## Fail-first and mutation evidence

The code under test did not exist on `origin/main`, so a bare "fails before the fix" is trivially true. In
addition, mutants of the shipped logic were applied and reverted (details in the step-03 handoff):

|---|---|
| CHK-24 gateway default check disabled (`-> false`) | 7 |
| CHK-23 reverse walk replaced by forward walk | 23 |
| `may_write?` SERVICE_TASK -> `false` | 1 |
| `RoleBinding.unbound/2` never filters | 4 |
| `activate/2` stops calling `Graph.validate_flow/1` | 2 |

## Fixture note (reported to ORCH, not a test defect)

The design lists 11 shipped fixtures that failed CHK-24 and were fixed in the implementation commit by adding
`<gateway>-default` edges whose targets are engineering proposals pending BA confirmation (design OQ-9). The
shipped-definitions test now pins that they pass; it does not judge the business correctness of those targets.
