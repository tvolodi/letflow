## Acceptance criteria -> tests

### AC1 -- one test per check, minimal violating definition + valid neighbour
* check 1 `:invalid_required_outputs`: unit `check 1 -- :invalid_required_outputs` (non-list x4 value types, non-string entries, empty / whitespace string, duplicate (x2, x3), two duplicated keys, two bad nodes); valid neighbour `["decision"]`, `[]`, `nil`, absent.
* check 1 `:required_outputs_on_non_human_task`: unit, EXCLUSIVE_GATEWAY and SERVICE_TASK (even with malformed value: only the non-human code); valid neighbour: SERVICE_TASK with `required_outputs: nil`.
* check 2: unit `check 2 -- ... (validate/2, non-empty declared_fields)` message equality `"Node 't' (HUMAN_TASK) has required_outputs key 'decision' with no variable_schema"`; valid neighbour with the schema declared.
* check 3: unit `check 3 -- decision_key_warnings/2` (prefix, key, definition, edge id, producer); valid neighbour `required_outputs: [decision]`.
Why: each asserts code/prefix AND node id AND key (the AC), and the neighbour differs from the violator in exactly the one attribute.

### AC2 -- surfaces
* create/update reject `:invalid_required_outputs`: surfaces file `check 1 at create/2 and update/3` (create non-list, duplicate, empty, non-human; update leaves the stored graph equal to the original; nothing stored on create). HTTP: router file `check 1 over HTTP` (POST / 422 with `errors[].code`, PUT, PATCH, /import).
* check 2 reported by validate, refused by activate, NOT rejected at create: surfaces `check 2 at validate_definition_graph/2 and activate/2` + `create/2 does NOT reject a key with no variable_schema`; router `check 2 over HTTP` (POST / 201, /validate 422, /activate 422 and definition stays DRAFT; after registering the schema, activate succeeds in the context test).
* check 3 warning in validate 200 body and pack-install result, not in the activate response: surfaces `check 3 at ...` (activate result has no `:warnings` key and no `decision_key_not_required` text) and `SolutionPack.install/3` (warning in `result.warnings`, install still succeeds, none when declared); router `check 3 over HTTP` (`warnings` carries the line, `status` "valid", `findings` []; activate 200 body has no `warnings` key and no substring).
* Check 2 not run at pack install and check 1 run at install (non-list fails the install, nothing stored): surfaces `SolutionPack.install/3`.
* `ValidationWarnings.for_definitions/2`: ordering (every `unbound_task_role:` line before every `decision_key_not_required:` line; decision lines in input definition order), all elements `is_binary/1`; `[]` for no definitions / a clean definition.

### AC3 -- empty-schema trap
* unit `check 2 -- the empty-declared_fields exemption does not hide it` (`validate(graph, %{})` is `valid: false` with the check-2 code; per key and node counting; clause returns ONLY check 2 even with another class present; valid neighbour with no `required_outputs` stays `%{valid: true, violations: []}`).
* DB/HTTP: a definition with NO `variable_schemas` rows validated (context and `POST /:id/validate`).

### AC4 -- negative tests: node id and key, duplicate, non-list
Unit and surfaces assertions on `message` (`Node 't'`, `'decision'`, `'risk'`); duplicate and non-list each reported once; check 2 reads totally (malformed attribute and non-human node ignored, never raises).

### AC5 -- check 3 behaviour
Unit: warning on a HUMAN_TASK edge and on an EXCLUSIVE_GATEWAY edge; declared by the producer, by a different upstream HUMAN_TASK; not suppressed by a declaration on a sibling (non-ancestor); key no HUMAN_TASK produces (service response upstream, start variable, open HUMAN_TASK without `form_schema`) yields none; producer downstream of the reader does not count; one warning per (edge, key) in order of first appearance, nested path on its root; producer list sorted; blank / unparsable condition never raises; never a violation (`validate/2` valid with and without declared fields, attribute check clean). DB/HTTP: validate stays valid with the line in `warnings`.

### AC6 -- `required_outputs` on a non-HUMAN_TASK node
Unit (gateway, service task), surfaces (create), router (POST / 422 naming `gw`).

### AC7 -- shipped definitions
`required_outputs_shipped_definitions_test.exs`: 13 shipped definitions (7 `test/fixtures/qa/*.json`, 6 `test/fixtures/simulation/**/process_*.yaml`; `priv/` ships none) run through CHK-25 and `SemanticValidation.validate/2` with the fixture's own registered `variable_schemas` and `decision_key_warnings/2`. Asserts new violations == 0 per definition; prints `REQ-461 shipped-definition findings: <path> violations=<n> warnings=<n>`; never fails on warnings. A discovery guard (>= 12, >= 6 QA, >= 6 simulation) prevents an empty pass. No definition was weakened (no fixture or lib file touched).

### AC8, AC9 -- compile/format/boundaries/scoped run; SECURITY-REVIEWER not required
Not executable surface of their own; reported in the handoff (format check and two scoped runs, 70 passed each).

## Not asserted, on purpose

* The pack-install shape failure asserts `inspect(reason) =~ "invalid_required_outputs"`, because the install error is a wrapped rollback reason; the stored-row count (0) is the strict half.
* Mutation measurement is left to TEST-DESIGN-VALIDATOR (this requirement's code exists; no regression-of-nonexistence claim is made).
