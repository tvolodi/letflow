## The twelve per-node tests (AC2) -- named by node id

Each starts with the node id, runs on the REAL fixture and the REAL engine, and does the same thing in two steps:

1. `assert_omitted_refused!`: completes the node THREE ways with the key omitted -- `%{}`, `%{key => nil}`, and an
   output carrying only other keys (for severity: `false_positive: false`, i.e. the other decision supplied but not the
   required one) -- and for each asserts `{:error, {:output_refused, %{missing_keys: [key], rejected_keys: []}}}`
   (the engine-side shape the tasks router renders as 422 `output_refused`, pinned by
   `routers/tasks_required_outputs_test.exs`), the task still `:pending`, the instance projection (status,
   current_nodes, variables) identical, no new event, no `EXECUTION_ERROR`.
2. Completes with a valid value and asserts the route taken (on fresh instances for a second value where cheap).

| a | `ops-review:` | 100 approve -> release-shipment (old fail-closed ceo-approval NOT taken); 900 approve -> ceo-approval | proves omission no longer escalates silently |

## Former KNOWN LIMITATION tests (AC3)

Removed from `swiftroute_decision_forms_fixture_test.exs`; `grep -rn "KNOWN LIMITATION" test` returns nothing.
Former assertions (quoted): ops-review omitted -> `proj.status == :active`, `proj.current_nodes == ["ceo-approval"]`,
`refute Map.has_key?(proj.variables, "ops_decision")`; ceo-approval omitted -> `proj.current_nodes == ["auto-reject"]`,
`refute "release-shipment" in proj.current_nodes`. Replaced by tests a and b above, which assert refusal, task open,
instance unchanged and a retry that routes. The moduledoc and the `assert_rejected!` comment were reworded.
Also fixed: `assert_rejected!` expected `rejected_keys: [key]` for every bad value; a `nil` decision is MISSING
(`missing_keys: [key], rejected_keys: []`, BA 2026-10-07), an out-of-enum / empty-string value is REJECTED
(`missing_keys: [], rejected_keys: [key]`). The helper now asserts the real shape per case, no weakening.
